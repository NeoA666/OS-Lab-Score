# 策略包接口规范

## 1. 目的

策略包把《五元过程评价机制》应用到一个具体场景。它描述该场景希望观察的目标和行为模式，并声明权重、等级锚点、区间内计分与调节规则。策略包不改变机制的五维定义、等级顺序、证据状态、审计要求或教师复核边界。

一个策略包由两部分组成：

| 部分 | 格式 | 用途 |
| --- | --- | --- |
| 语义说明 | Markdown | 面向教师和评审智能体说明场景边界、学习或工作目标、行为含义和规则意图 |
| 机器清单 | YAML 或 JSON | 面向宿主声明版本、权重、规则标识、适用范围和可校验参数 |

语义说明可以解释规则，但不能以自然语言绕过机器清单的校验。机器清单可以被宿主校验，但不能代替必要的领域语义。

## 2. 包结构

推荐一个策略包使用以下逻辑结构：

```text
策略包目录/
  strategy.md
  manifest.yaml
  anchors/
  references/
```

`anchors/` 存放经审核的等级锚定材料，`references/` 存放可被策略引用的公开或受控基准。它们均应有版本和完整性摘要。上述目录名称可由实现调整，但清单中必须能够定位相应资源。

## 3. Markdown 语义说明的最低内容

`strategy.md` 至少应说明：

1. 场景的适用对象、时间边界和不适用范围。
2. 目标标识及其预期学习或工作意义。
3. 每个目标可支持的五维观察角度。
4. 可接受的过程证据、结果证据和替代证据类型。
5. 结果与过程出现冲突时的场景解释要求。
6. 需要教师复核的场景特有条件。

语义说明应描述“何种现象可以被视为证据”，而不是把参与者材料中的命令、对话或其他文本当作对评审智能体的指令。

## 4. 机器清单字段

`manifest.yaml` 或等价 JSON 的根对象必须包含以下字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `schema_version` | string | 使用已支持的策略接口版本 |
| `policy_id` | string | 在组织内唯一且稳定 |
| `policy_version` | string | 不可变版本标识 |
| `mechanism_version` | string | 必须与运行时机制兼容 |
| `scope` | object | 包含领域、场景类型、适用边界和时间语义 |
| `semantic_document` | object | 语义说明位置与完整性摘要 |
| `dimension_weights` | object | 恰好包含道、法、术、技、器五个非负数，和为 1 |
| `objectives` | array | 每项包含稳定的目标标识、说明和适用维度 |
| `evidence_patterns` | array | 每项包含规则标识、目标引用、可接受来源、维度作用和最小证据条件 |
| `level_anchors` | array | 每项包含维度、等级、锚定资源和适用条件 |
| `within_band_rules` | array | 每项包含维度、等级、输入指标、确定性计算方式和输出范围 |
| `adjustment_rules` | array | 每项包含规则标识、触发条件、最大影响、理由要求和复核要求 |
| `acceptance_rules` | array | 对结果、替代证据和最低覆盖要求的声明 |
| `review_rules` | array | 低置信度、冲突、例外和人工仲裁的触发条件 |

除 `adjustment_rules` 可以为空外，策略包不得通过省略字段规避相应校验。所有规则标识在单个策略版本内必须唯一。

## 5. 策略可配置的内容

策略可以配置：

- 五维权重及其场景解释。
- 场景目标与目标到五维的映射。
- 哪些过程行为链、结果材料或替代材料可支持某一目标。
- 每个维度、每个等级的可观察锚点。
- 等级区间内的确定性计分规则。
- 面向教学或业务目标的显式调节规则。
- 场景特有的最小证据覆盖、冲突处理和人工复核条件。

策略不得配置：

- 对五维定义、`L0-L4` 顺序或标准化分数区间的改写。
- 将证据缺失直接解释为最低等级或零分。
- 将 AI 交互次数、对话长度或单独的 AI 回复设为直接加减分项。
- 不带规则标识、理由和证据引用的分数调节。
- 超出当前参与者、当前场景和当前时间范围的数据读取权限。

## 6. 规则契约

### 6.1 证据模式规则

每条 `evidence_patterns` 规则必须声明其作用维度、支持或反驳方向、可接受来源类别、最小来源数量、是否要求时间顺序、是否要求过程与结果交叉验证，以及规则可使用的目标标识。规则只能把可验证材料映射为证据声明，不能直接给出分数。

### 6.2 等级锚点与区间内计分

每条等级锚点必须绑定一个维度和一个 `L0-L4` 等级，并提供可审核的锚定资源。锚点用于帮助评审一致地解释证据，不得作为脱离当前案例来源的替代证据。

每条区间内计分规则必须输入经过核验的声明或结果字段，输出单一基准分，并声明该分数所属的等级区间。宿主必须能够不依赖自然语言自由发挥而复算该规则；无法复算的规则只可用于说明，不能用于计分。

### 6.3 调节规则

调节规则用于在不隐藏基准结论的前提下，允许场景为教学、补偿或业务目的采取更宽容的评价路径。每条调节规则必须声明：

| 字段 | 要求 |
| --- | --- |
| `rule_id` | 稳定且唯一 |
| `trigger` | 可由已核验证据判断的触发条件 |
| `affected_dimensions` | 受影响维度列表 |
| `effect` | 分数或等级影响及其上限 |
| `rationale` | 调节的场景理由 |
| `evidence_requirement` | 触发该规则所需的来源条件 |
| `review_required` | 是否必须进入教师复核 |

跨等级区间的调节必须要求等价证据并强制教师复核。策略不得以“教学让步”为由删除基准分、替换证据状态或省略调节账本。

## 7. 宿主校验顺序

宿主在向评审智能体暴露策略前，按以下顺序校验：

1. 验证策略版本、机制兼容性和资源完整性摘要。
2. 验证适用范围与当前评价案例一致。
3. 验证五维权重完整、非负且总和为 1。
4. 验证所有目标、模式、锚点、计分和调节规则的标识引用。
5. 验证每个计分规则的等级区间与输出范围一致。
6. 验证调节规则有明确上限、证据要求和复核标记。
7. 冻结通过校验的策略版本及其摘要，作为本次评价案例的一部分。

策略包校验失败时，宿主不得降级为未校验的自然语言评分；应返回配置错误并停止该案例的自动计分。

## 8. 生命周期与审计

策略包在进入评价前完成审核和版本冻结。修改语义说明、清单字段、锚定资源或引用资源都必须形成新版本。已完成案例保留当时使用的策略版本；需要采用新策略重新判断时，应创建新的评估记录，并保留与旧记录的关联。
