# 五元过程评价机制

## 1. 定位与适用范围

本文件定义一套可迁移的过程评价机制。它用于对一个参与者在一个有明确边界的学习、训练或工作场景中的过程表现形成五维建议评估。机制关注评价如何成立，不规定某个场景应观察什么行为，也不规定某个场景的权重、题目、验收条件或加分规则。

本版本的最小评价单元为一个评价案例。每个案例至少包含参与者标识、场景标识、时间范围、数据清单及其版本、机制版本、策略包标识和策略包版本。机制只评价该案例边界内可验证的材料，不对缺失范围作推断，也不承担跨场景成长曲线或课程总评的聚合。

## 2. 机制、策略与术的边界

| 概念 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 评价机制 | 五维语义、等级骨架、证据协议、计分边界、审计记录、复核状态 | 场景目标、权重、行为规则、具体让步 |
| 策略包 | 场景语义、目标、行为模式、维度权重、等级锚点、区间内计分规则、调节规则 | 改写五维定义、等级顺序、证据状态含义或审计要求 |
| 领域中的术 | 对领域机制、因果路径和操作方法的理解与运用 | 对评分规则的选择 |

“术”是被评价的五维之一；“策略”是评价系统在特定场景中应用机制的配置。两者不得混用。

机制必须持续满足下列约束：

1. 每个判断都必须可回溯到具体证据。
2. 缺少证据不等于能力不足。
3. 模型推断不是独立证据，不能替代来源记录。
4. 策略可以放宽满足路径或调节建议分，但不能隐藏基准结论、伪造证据或覆盖证据状态。
5. 建议分在教师复核前不得作为最终发布分数。

## 3. 五维语义

| 维度 | 核心问题 | 评价对象 |
| --- | --- | --- |
| 道 | 为什么做，服务何种目标与价值，边界何在 | 目标理解、价值判断、系统视角、边界意识 |
| 法 | 凭什么约束，采用何种原则、抽象和契约 | 原则辨识、约束遵守、架构关系、接口与规则理解 |
| 术 | 通过什么机制、因果路径和操作方法实现 | 因果模型、机制解释、方法选择、路径判断 |
| 技 | 能否可靠地实施、调试、验证和修正 | 可重复操作、实现质量、诊断能力、验证能力 |
| 器 | 使用什么工具、环境、载体和可观察产物 | 工具选择与使用、环境辨识、载体定位、结果读取 |

五维是并列的观察视角，不是由低到高的能力阶梯。同一来源材料可支持多个维度，但每一次使用都必须说明该材料在该维度中的独立作用，不能因重复引用而重复累加分数。

## 4. 统一等级与分数区间

所有维度使用相同的五级骨架。`L0-L4` 是稳定的机器标识，展示名称可以由后续产品层决定。

| 等级 | 通用语义 | 标准化建议分区间 |
| --- | --- | --- |
| L0 | 未能形成有效的相关识别、判断或行动，或关键错误在证据范围内未被修正 | 0-19 |
| L1 | 能识别相关对象、规则或现象，并在明确支持下作出有限回应 | 20-39 |
| L2 | 能在已知约束内独立完成边界清晰的行动、解释或验证 | 40-59 |
| L3 | 能说明因果关系，定位问题，并基于证据作出修正或选择 | 60-79 |
| L4 | 能将理解迁移到新条件，形成系统性判断或提出有依据的改进 | 80-100 |

等级只表达已观察到的学习成熟度，不表达参与者的固定能力上限。策略包为各维度提供与场景匹配的等级锚点，但不得改变等级顺序或区间边界。

策略包必须声明区间内计分规则。宿主负责验证基准分落在相应等级区间内。若策略调节使建议分跨越等级区间，必须显式记录为等级调节，列出规则标识、等价证据、影响和理由，并自动进入教师复核；宿主不得执行无记录的跨级调整。

## 5. 证据模型

### 5.1 来源、观察与判断

来源记录、观察事实和评价判断必须分层保存：

- 来源记录是原始或清洗后的可读取材料。
- 观察事实是对来源中可直接定位内容的陈述。
- 证据声明是在观察事实基础上，对某个维度形成的、可反驳的判断。

每条证据声明至少包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `claim_id` | 声明的唯一标识 |
| `dimension` | 道、法、术、技或器 |
| `polarity` | `support`、`contradict` 或 `context` |
| `observation` | 可由来源直接核对的观察事实 |
| `inference` | 基于观察形成的有限推断 |
| `source_refs` | 来源标识、不可变摘要、事件或行范围、摘录 |
| `temporal_context` | 时间、顺序、场景上下文及其不确定性 |
| `evidence_level` | 来源等级 |
| `confidence` | 对本声明的置信度，不等同于分数 |
| `limitations` | 缺失、截断、关联不确定或其他限制 |
| `usage_key` | 用于发现重复计分的证据使用标记 |

来源等级采用以下含义：

| 等级 | 含义 | 使用限制 |
| --- | --- | --- |
| E1 | 可直接核验的原始、只读记录 | 可作为高强度来源 |
| E2 | 带有来源定位和完整性信息的清洗、重放或派生记录 | 可作为有效来源，但必须保留其处理限制 |
| E3 | 模型摘要、聚合结论或人工转述 | 只能辅助解释，不能脱离 E1 或 E2 单独支撑等级或分数 |

### 5.2 AI 交互作为过程证据

AI 交互是重要的过程证据来源。它可以揭示参与者如何提出问题、理解外部信息、采取行动、验证结果、修正判断或形成反思。一次完整的学习过程链通常由下列可选环节构成：

`问题或意图 -> 信息吸收 -> 参与者行动 -> 结果验证 -> 修正或反思`

并非所有有效声明都必须覆盖全部环节，但声明学习发生或理解提升时，必须引用足以建立关联的参与者行为和后续可观察结果。单独的 AI 回复、单独的提问次数或对话长度不能证明学习，也不能直接产生加分或扣分。高质量、可追溯的交互链可以成为强证据；交互较少但存在充分独立证据的参与者也可以获得高等级。

### 5.3 过程与结果的交叉验证

代码、产物、测试和其他结果材料用于验证过程判断。结果正确不能自动证明所有维度达成，过程丰富也不能自动替代结果验证。当过程证据与结果证据存在实质冲突时，相关维度必须标记冲突并进入复核。

同一来源可以被多个声明引用，但宿主必须保存每一次引用的维度、角色和计分影响。一个来源不得以同一理由在同一维度内重复贡献分数。

## 6. 维度结论、计分与复核

每个维度结果必须包含以下内容：

| 字段 | 要求 |
| --- | --- |
| `overall_status` | `sufficient`、`insufficient`、`conflicted` 或 `review_required` |
| `baseline_level` | 在证据充分时为 `L0-L4`，否则为空 |
| `baseline_score` | 按策略的区间内规则计算，必须落在基准等级区间内 |
| `policy_adjustments` | 调节规则、影响、理由和来源引用的数组；没有调节时为空数组 |
| `final_level` 与 `suggested_score` | 调节后的建议结论；未满足发布条件时仅作为草稿 |
| `confidence` | 对该结论的置信度 |
| `claims` | 支持、反驳和上下文声明的引用 |
| `review` | 是否需要教师复核、原因和处理结果 |

`insufficient` 表示当前案例范围内没有达到最低覆盖要求的证据，`baseline_level` 和 `baseline_score` 必须为空，不能以 L0 代替。`conflicted` 表示存在未解决的实质矛盾。`review_required` 表示结论受到冲突、低置信度、跨级调节、异常数据或规则例外影响；报告应同时保留其基础证据状态和复核原因。

五维权重完全由策略包声明。宿主必须验证权重非负、键集完整、总和为 1，并将权重版本写入结果。只有所有被策略要求参与总分的维度达到可发布状态时，宿主才可计算场景建议总分；否则场景结果为不完整，而不是以缺失维度的零分代替。

建议总分由宿主以确定性方式汇总已确认的五维建议分。模型负责提出证据声明和维度草稿，不负责绕过权重、区间、状态或复核规则。

## 7. 审计与变更控制

每次运行必须固定并保存机制版本、策略包版本、数据清单摘要、来源引用、模型或人工处理记录、维度草稿、核验结果、调节账本和教师复核结论。任何后续重评都应能依据这些信息重建同一案例的输入范围和判断依据。

机制版本变更只能修改机制文档和对应的宿主实现，并应通过新版本发布。策略包变更不得追溯覆盖已完成案例；需要重评时，应以新策略版本生成新的评估记录。评价过程对学生材料保持只读，报告和审计记录由宿主在独立输出位置保存。
