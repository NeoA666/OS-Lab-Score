## 基础知识

### xv6-k210 文件系统层次

xv6-k210 与原版 xv6 不同，使用 FAT32 而非日志文件系统。文件系统涉及的层次：

```text
进程打开文件表 ofile[NOFILE]   (NOFILE = 16)
        │
        │ 每项指向一个 struct file
        ▼
struct file {
    type, ref, readable, writable
    struct dirent *ep   ←─ 指向 FAT32 目录项
    uint off             ←─ 当前读写偏移
    ...
}
        │
        ▼
struct dirent (FAT32 目录项)
    name, inum, valid, parent, ...
```

- **fd（文件描述符）**：用户态拿到的整数，本质是进程 `ofile[]` 数组的下标
- **file 对象**：内核中"一次打开"的抽象，记录读写偏移、引用计数、指向的目录项
- **dirent**：FAT32 中真实的目录项，对应磁盘上的文件或子目录

### 文件描述符与引用计数

同一个文件可以被多次打开，产生多个 file 对象；也可以通过 `dup` / `dup2` 让多个 fd 共享同一个 file 对象。file 对象的 `ref` 字段记录被多少 fd 共享，`filedup` 让 ref++，`fileclose` 让 ref--，ref 减到 0 才真正释放。

```text
dup(1) / dup2(1, 5) 后：
ofile[1] ──┐
            ├─→ 同一个 struct file {ref=2}
ofile[5] ──┘
```

关闭其中一个 fd（如 `close(1)`），file 对象的 ref 减为 1，对象本身还在；只有 `close(5)` 后才真正释放。这是 shell 重定向（`> file`）和管道（`|`）共享 fd 的基础。

### FAT32 目录项（dirent）

`struct dirent` 是 FAT32 文件系统的核心数据结构，每个文件或子目录都对应一个 dirent。dirent 在内核中可能处于：

- `valid == 0`：未加载，需要从磁盘读
- `valid == 1`：已加载到内存，可以读写
- `valid == -1`：被 `eremove` 标记为已删除

遍历目录需要 `enext(dp, ep, off, count)` 接口：从父目录 `dp` 的偏移 `off` 处读下一个目录项到 `ep`。`dirnext(f, addr)` 是 file.c 提供的封装，把 `enext` 与 file 的偏移量管理结合，常用于 `readdir`。

### `dup` 与 `dup2`

xv6-k210 已有 `sys_dup`：

```text
dup(oldfd) → 自动找最小可用 fd 作为 newfd，复制 oldfd 到 newfd
```

Linux 风格的 `dup2(oldfd, newfd)` 让用户**指定**目标 newfd：

```text
dup2(oldfd, newfd) → 复制 oldfd 到 newfd，newfd 已打开则先关闭
返回值：成功返回 newfd，失败返回 -1
```

### `readdir` 与 `getdents`

xv6-k210 已有 `sys_readdir`，通过 `dirnext` 遍历目录，每次返回一个目录项信息到用户态。Linux 风格的 `getdents(fd, buf, len)` 语义类似但缓冲区格式不同（按 `linux_dirent` 结构填充），用户程序遍历完所有目录项。

本 lab 主线只做简化版：复用 `dirnext` 或 `enext` 把目录项写到用户 buf，不严格对齐 Linux 格式。

### `remove` 与 `unlink`

xv6-k210 已有 `sys_remove`，通过 `eremove` 删除 FAT32 目录项。Linux 风格的 `unlink` 语义等价于 `remove`（删除文件，对硬链接是减引用计数，本 lab 简化为直接删除）。本 lab `unlink` 直接复用 `sys_remove` 的实现路径。

### 关键参考实现

#### `sys_dup`（`kernel/sysfile.c` 约 62 行）

`sys_dup` 是 `sys_dup2` 的最佳参照物：

```c
uint64
sys_dup(void)
{
  struct file *f;
  int fd;

  if(argfd(0, 0, &f) < 0)
    return -1;
  if((fd=fdalloc(f)) < 0)
    return -1;
  filedup(f);
  return fd;
}
```

- `argfd(0, 0, &f)`：把第 0 个参数解释为 fd，校验合法性，把对应的 file 指针写到 `f`
- `fdalloc(f)`：在进程 `ofile[]` 中找最小可用下标，把 `f` 放进去
- `filedup(f)`：增加 file 对象的引用计数
- 返回新分配的 fd

`sys_dup2` 的差别在于：不调 `fdalloc` 自动找下标，而是**直接用参数指定的 newfd**；如果 newfd 已打开则先 `fileclose`。

#### `sys_readdir`（`kernel/sysfile.c` 约 321 行）

```c
uint64
sys_readdir(void)
{
  struct file *f;
  uint64 p;

  if(argfd(0, 0, &f) < 0 || argaddr(1, &p) < 0)
    return -1;
  return dirnext(f, p);
}
```

- `argfd(0, 0, &f)`：取 fd 并校验
- `argaddr(1, &p)`：取用户态缓冲区地址
- `dirnext(f, p)`：从 `f->ep` 指向的目录中读下一项，写到用户地址 `p`

`sys_getdents` 复用这个模式：fd 校验、用户缓冲区读取、循环调 `dirnext` 或 `enext` 写到 buf。

#### `sys_remove`（`kernel/sysfile.c` 约 381 行）

```c
uint64
sys_remove(void)
{
  char path[FAT32_MAX_PATH];
  struct dirent *ep;
  int len;
  if((len = argstr(0, path, FAT32_MAX_PATH)) <= 0)
    return -1;
  /* ... 路径合法性检查、namei 解析、eremove 删除 ... */
}
```

- `argstr(0, path, FAT32_MAX_PATH)`：从用户态读字符串到内核缓冲区 `path`
- 路径合法性检查（不能删 `.` / `..`）
- 通过 `namei` 解析路径得到 dirent
- 调 `eremove` 删除目录项

`sys_unlink` 与 `sys_remove` 语义等价，可以直接复用相同路径。

### 三个 CP 在调用链中的位置

```text
用户调用
  ↓
sys_dup2     CP① ─→ argfd(oldfd) + 直接赋 ofile[newfd] + filedup
sys_getdents CP② ─→ argfd(fd) + dirnext/enext 循环 + 写用户 buf
sys_unlink   CP③ ─→ argstr(path) + namei + eremove
```

三个 CP 相对独立，但建议按顺序：dup2 复杂度中等（要处理引用计数），getdents 涉及目录遍历，unlink 最简单（参考 remove）。

### 任务2：CP① 实现 `sys_dup2`

#### 步骤1：阅读 `sys_dup`（约 62 行）

源码见"代码导读"。注意四个步骤：argfd 取 fd → fdalloc 找空位 → filedup 增加 ref → 返回新 fd。

#### 步骤2：理解 `dup2` 与 `dup` 的差别

`dup2(oldfd, newfd)` 不调 `fdalloc`，而是直接使用参数 `newfd`。具体行为：

- `oldfd` 必须已打开（用 `argfd` 校验）
- `newfd` 必须在 `[0, NOFILE)` 范围（`NOFILE = 16`）
- 若 `newfd == oldfd`：直接返回 newfd，不做操作
- 若 `ofile[newfd]` 已打开：先 `fileclose(ofile[newfd])`，再覆盖
- 把 `ofile[newfd] = f`，调 `filedup(f)` 增加引用计数
- 返回 newfd

#### 步骤3：阅读辅助函数 `argfd` 和 `fdalloc`（`kernel/sysfile.c` 约 28 / 47 行）

`argfd(n, 0, &f)` 把第 n 个 syscall 参数解释为 fd，校验 `0 ≤ fd < NOFILE` 且 `ofile[fd] != NULL`，把对应 file 指针写到 `&f`。CP① 可以复用它取 `oldfd` 的 file 指针。

`newfd` 这边不需要 `fdalloc`（因为目标位置已指定），但要手动读 fd 整数：`argint(1, &newfd)`。

#### 步骤4：实现 `sys_dup2`

`sys_dup2`（约 183 行）当前是占位 `return -1;`。实现思路：

1. 用 `argfd(0, 0, &f)` 取 oldfd 对应的 file 指针
2. 用 `argint(1, &newfd)` 取 newfd 参数
3. 检查 `newfd` 范围 `0 ≤ newfd < NOFILE`
4. 若 `newfd == oldfd` 直接返回 newfd（可由 `argfd` 顺带拿到的 pfd 比较，或单独取 oldfd 整数）
5. 若 `ofile[newfd]` 已打开：`fileclose(ofile[newfd])`
6. `myproc()->ofile[newfd] = f;`
7. `filedup(f);`
8. 返回 newfd

实现完成后重新构建运行 `fstest`，期望输出：

```text
lab7 dup2 test passed (this line via fd 5)
```

### 任务3：CP② 实现 `sys_getdents`

#### 步骤1：阅读 `sys_readdir`（约 321 行）

源码见"代码导读"。它只读一个目录项，通过 `dirnext(f, p)` 把信息写到用户地址。

#### 步骤2：理解 `getdents` 的语义

`getdents(fd, buf, len)` 从 fd 对应的目录读若干目录项，写到用户缓冲区 `buf`，最多写 `len` 字节。返回实际写入的字节数；读到目录末尾返回 0；出错返回 -1。

简化版实现：

- 用 `argfd(0, 0, &f)` 取 file 指针
- 检查 `f->type == FD_ENTRY` 且 `f->ep` 是目录（dirent 的 `attribute & ATTR_DIRECTORY`）
- 用 `argaddr(1, &buf)` 取用户缓冲区地址，用 `argint(2, &len)` 取长度
- 循环调 `dirnext` 或 `enext`，每项用 `copyout2` 写到用户 buf
- 返回总写入字节数

#### 步骤3：实现 `sys_getdents`

`sys_getdents`（约 216 行）当前是占位 `return -1;`。主线不要求严格对齐 Linux `linux_dirent` 格式，能遍历、能写回用户态、能区分目录项即可。具体实现可以参考 `dirnext` 在 `file.c` 中的写法。

#### 步骤4：手动验证

`fstest` 不测 `getdents`，需要手动小用例：写一个程序打开 "."，循环调 `getdents`，打印读到的目录项名。期望至少看到 `README`、`init`、`sh` 等已存在的用户程序。

### 任务4：CP③ 实现 `sys_unlink`

#### 步骤1：阅读 `sys_remove`（约 381 行）

源码见"代码导读"。完整路径：`argstr` 取路径 → 合法性检查 → `namei` 解析 → `eremove` 删除。

#### 步骤2：理解 `unlink` 与 `remove` 的关系

Linux 的 `unlink` 删除文件（对硬链接是减引用，本 lab 简化为直接删除）。xv6-k210 的 `remove` 语义等价：删除文件或空目录。本 lab `unlink` 可以直接复用 `sys_remove` 的实现，或者把 `sys_remove` 的核心逻辑提取出来供两者调用。

#### 步骤3：实现 `sys_unlink`

`sys_unlink`（约 245 行）当前是占位 `return -1;`。实现思路：完全照搬 `sys_remove` 的路径读取、检查、解析、删除逻辑。可以考虑提取公共函数 `remove_path(char *path)` 让两者复用，但主线只要求 `unlink` 能正确删文件。

#### 步骤4：手动验证

写一个小程序：先创建临时文件（用 `open` + `close`），调 `unlink` 删除，再用 `open` 尝试打开应失败。或在 shell 中执行：

```text

（应看到 tmp.txt）

（shell 的 rm 内部走 unlink）

（应不再看到 tmp.txt）
```

注意 shell 自带的 `rm` 命令是否走新加的 `unlink`，取决于 shell 实现。手动小程序更直接。

## 常见问题（FAQ）

| 现象 | 原因 / 解决 |
|------|------------|
| `fstest` 输出 `dup2 FAILED` | CP① 没实现，或 argfd/argint 失败 |
| `dup2` 后写 newfd 无输出 | `filedup` 没调用，或 ofile[newfd] 没正确赋值 |
| `getdents` 读出乱码 | 没用 `copyout2` 写用户 buf，或目录项格式不对 |
| `getdents` 对普通文件不报错 | 没检查目录属性，普通文件 fd 不应被接受 |
| `unlink` 后文件还在 | `eremove` 失败没检查，或路径解析错 |
| 系统启动失败 | 误改了 fat32.c 等基础设施。本 lab 只动 sysproc.c |
| `make build` 报 sys_dup2 undefined | syscalls[] 已预填，但 sysproc.c 函数名拼写错 |

## 思考题（可选）

下列题目用于加深理解：

1. **`dup2` 复制后，oldfd 和 newfd 共享同一个 file 对象吗？关闭一个会影响另一个吗？** 提示：看 ref count 的语义。
2. **为什么 `argfd` 既输出 fd 整数（pfd）又输出 file 指针（pf）？** 提示：调用方可能只需要其中之一。
3. **`getdents` 的 buf 格式为什么常按 `linux_dirent` 而非简单的字符串数组？** 提示：每个目录项需要带 inode 号、记录长度、文件名等。
4. **`unlink` 和 `rename`、`remove` 在底层 FAT32 操作上有什么共同点？** 提示：都是修改目录项，最终落到 `eremove` 或类似函数。
5. **xv6-k210 为什么用 `dirent` 而不是 `inode`？** 提示：FAT32 文件系统的设计本就没有 inode 概念。
