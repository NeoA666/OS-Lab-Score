# 2026-09-19 代码差异报告比较范围修复（纳入 lab0）

## 问题

`代码差异报告工具/generate_lab_diff_reports.py` 把比较范围硬编码为 lab1–lab8：

```python
LABS = tuple(f"lab{number}" for number in range(1, 9))
```

因此 lab0 被整体排除，个人目录与汇总目录都只有 lab1.md–lab8.md。但基准仓库 `xv6-ai-labs-km-无答案` 存在 `lab0` 至 `lab8`；上级清洗工具支持 lab0–lab8；诚信审核系统按 `(lab[0-8])\.md` 与 `代码差异报告/{lab}.md` 读取材料。lab0 的缺失使“学生 labs/lab0 对比基准 lab0”这一对应关系无法体现，个人目录里也没有 lab0 的源码差异证据。

## 修复

- `LABS` 改为 `range(0, 9)`，比较范围变为 lab0–lab8；对应规则保持不变：**学生的 `labs/labN` 对比基准根目录下对应的 `labN`**。
- 同步更新脚本 docstring、`--all-labs` 帮助文本，以及 `README.md`、`背景信息.md` 中“lab1 至 lab8 / lab0 不在比较范围内”的说明。
- 新增回归测试 `test_lab0_is_in_scope_and_compares_against_the_reference_lab0`：断言 `LABS` 覆盖 lab0–lab8、`--lab lab0` 生成的报告基准目录指向基准 `lab0`，且个人清单登记 `lab0.md`。

lab0 仍然沿用同一套文件范围（kernel、xv6-user、linker 下的源码/脚本/构建配置与根目录 Makefile）、空白符策略和清单/链接安全校验，没有为 lab0 另开分支。
