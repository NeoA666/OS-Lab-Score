# AI/人工贡献识别 v3 对接文档

## 定位

AI/人工贡献识别是原始数据清洗后的独立补充阶段。它按“一个学生目录 + 一个 `labN`”生成 `assessment_labN.json`，供未来重构的诚信判别系统读取。它不修改现有诚信判别系统，不直接改变其输入、规则、结论或评分机制。

机器接口只有 `assessment_labN.json`。`完整贡献识别报告_labN.md` 与 `教师贡献复核报告_labN.md` 是受限的人工阅读渲染，后续系统不得解析 Markdown 生成事实、证据或结论。

生产结果由 NVIDIA NIM 的主分析和独立 NIM 复核产生。assessment 不保存 API 密钥、原始模型响应或模型思维内容；下游也不得要求或尝试恢复这些内容。

## 发现与兼容性

稳定路径：

```text
操作系统实验数据记录-已清洗/<学生目录>/AI人工贡献识别/
  assessment/
    assessment_labN.json
  完整贡献识别报告/
    完整贡献识别报告_labN.md
  教师贡献复核报告/
    教师贡献复核报告_labN.md
  .contribution_manifest.json
```

消费者以学生目录名和 `labN` 精确定位 assessment，先检查：

1. `schema_version == "ai-human-contribution-assessment/v3"`。v2 及未知主版本一律标为接口不兼容，不能静默映射旧字段。
2. `student.directory_name` 与当前审核学生目录相同，`lab` 与当前 Lab 相同。
3. `analysis_status`、`coverage`、`source_manifest`、`limitations` 和 `review` 是否允许进入下一步。

`.contribution_manifest.json` 仅供增量缓存和文件完整性检查，不能作为证据来源或结论输入。

### 顶层状态

| `analysis_status` | 含义 | 诚信系统处理 |
| --- | --- | --- |
| `complete` | 主分析和宿主结构校验已完成；独立复核状态见 `review`。 | 可作为补充材料进入本系统的证据复核流程。 |
| `insufficient_data` | 当前 Lab 的规定材料缺失或不足。`contribution_units` 必为空，`lab_conclusion.label` 必为 `indeterminate`。 | 只展示资料状态和局限；不能据此推断未使用 AI、人工完成或存在违规。 |
| `failed` | 输入读取、NIM 调用、NIM 独立复核、解析或宿主校验失败。 | 不使用其中的语义判断；按本系统的失败处理策略重试或提示。 |

### 输入清单和证据引用

`source_manifest` 是该任务可见或缺失的材料数组。每项固定包含 `source_id`、`kind`、`required`、`availability`、`relative_path`、`sha256`、`line_count` 和 `reason`。`coverage` 汇总资料覆盖状态和缺口。受控来源为：

| `kind` | 文件 |
| --- | --- |
| `timeline` | `简洁实验过程时间线/timeline_labN.md` |
| `terminal_qa` | `终端对话记录/terminal_qa_report_labN.md` |
| `command_statistics` | `终端命令统计/command_statistics_labN.md` |
| `diff_report` | `代码差异报告/labN.md` |

`lab0` 的 diff 为 `not_applicable`；`lab1` 到 `lab8` 的四项均是预期输入。`missing`、`invalid` 和 `not_applicable` 都只描述材料可见性，不能反向推断现实中的 AI 或人工行为。

`diff_hunks` 将 hunk ID 映射到 diff 文件与行范围。每个 `evidence_refs` 条目必须包含 `source_id`、相对路径、源文件 SHA-256、1 起始且两端包含的行范围，以及经脱敏、长度受限的 `excerpt`。证据引用有效前，消费者必须重新验证：

1. 路径没有越出当前学生目录，且来源文件仍属于同一 Lab。
2. 当前文件 SHA-256 等于 `sha256`。
3. `line_start` 和 `line_end` 合法，摘录在对应范围内；脱敏摘录不能要求逐字还原敏感文本。
4. 证据不能跨学生、跨 Lab 或跨源 ID 复用。

路径、哈希、范围或摘录不能验证时，该条引用无效。模型摘要、贡献标签和报告措辞不能代替原始来源验证。

### 贡献单元

`contribution_units` 是本接口的细粒度结果。每项均有以下稳定含义：

| 字段 | 含义与消费限制 |
| --- | --- |
| `unit_type` | `code_hunk` 指向一个或多个 diff hunk；`process_segment` 指向过程材料范围。 |
| `label` | 仅为 `ai_dominant`、`human_dominant`、`mixed`、`indeterminate`。它是当前材料的贡献画像，不是作者身份或粘贴方式。 |
| `behavior_roles` | 固定对象 `{ "ai": [...], "human": [...] }`，记录可观察到的 AI/人工角色，如解释、指导、生成、提问、实现、调试和验证。角色不是诚信规则命中。 |
| `confidence` | `strong`、`moderate` 或 `weak`。弱证据必须使用 `indeterminate`。 |
| `scope` | `code_hunk` 使用 `{ "hunk_id": "..." }`；`process_segment` 使用 `{ "source_id": "...", "line_start": n, "line_end": n }`。它限制结论的适用范围。 |
| `evidence_refs` | 该单元实际使用的可复核短引用。 |
| `summary`、`alternative_explanation`、`limitations` | 解释性文本和不确定性，不能替代源证据。 |

“AI 提供代码，学生阅读、修改、调试和验证后采用”可以在资料与行号足够支撑时得到 `human_dominant`，同时保留 `ai_code_generation` 等 AI 角色。此标签仍不能证明真实理解、手打、复制粘贴或独立作者身份。若证据不能区别这些可能性，必须是 `indeterminate`。

`lab_conclusion` 只汇总 Lab 级贡献画像，不得单独触发任何诚信等级。`review` 固定包含 `unit_reviews`、`overall_decision`、`reviewed_unit_ids` 和 `disagreement_unit_ids`；后两者是由单元复核记录派生的便利索引。`overall_decision` 在 `not_run` 时为 `null`。`review.status=disagreed` 时，`disagreement_unit_ids` 中的单元必须被下游视为 `indeterminate`，不用于不利推断。

`review.status` 仅使用 `agreed`、`disagreed` 或 `not_run`。已运行复核时，`unit_reviews[].decision` 与 `overall_decision` 使用 `agree` 或 `disagree`；它们与 `review.status` 的命名不同，消费者不应自行改写。`not_run` 表示独立复核没有完成，结果只能作为受限材料展示，不能据此提高诚信风险或影响评分。

## 推荐的诚信系统接入方式

未来诚信判别系统重构时，将本接口接入“补充过程/代码来源材料”层，按以下顺序处理：

1. 发现 assessment 后检查版本、身份边界和 `analysis_status`。
2. 读取 `coverage`、`source_manifest`、`limitations` 和 `review`，确定当前材料能支持的最高结论力度。
3. 对每个计划使用的 `evidence_refs` 重验路径、哈希和行范围，再由诚信系统自身分类为 E1、E2 或不可用。
4. 将贡献单元和总体画像仅作为教师复核与规则分流线索。Lab 规则注册表决定哪些已重验的原始证据可参与诚信判断。
5. 仍由诚信系统自身满足 R1/R2 所需的规则、过程证据和教师复核要求。

以下做法禁止：

- 仅凭 `ai_dominant`、`mixed`、`lab_conclusion`、代码 diff 或 Markdown 报告产生“高风险待核实”、违规或评分后果。
- 从 `human_dominant` 推断手打、未复制、真实理解或独立作者身份。
- 从 `indeterminate`、缺少 AI 对话、材料缺失或 `not_applicable` 推断没有使用 AI。
- 把 NIM 的语义判断、摘要或角色标签当作未经重验的 E1 原始事实。
- 从代码风格、功能相似、提交速度、命令频率或时间接近自行补充作者归因。

## 对接验收

诚信系统的重构测试至少应覆盖：

1. 完整 v3 assessment 在学生和 Lab 边界、哈希与行范围均匹配时，可显示为补充材料，但不会自动生成诚信结论。
2. `lab0` 只含 `process_segment`，其 diff 为 `not_applicable`，系统不会把无 diff 当成材料缺失或阴性结论。
3. `lab1` 至 `lab8` 缺少任一规定过程材料时，`insufficient_data` 只降低资料覆盖，不产生不利推断。
4. `review.status=disagreed` 的单元不用于风险提升；教师可以定位其哈希和行范围。
5. 篡改文件、跨学生/Lab 引用、哈希不一致、范围越界或不兼容 schema 时，系统拒绝对应证据。
6. 输出和展示均不包含 API 密钥、模型思维内容、原始 NIM 响应或完整来源文本。
