# OS Lab Score

面向 xv6 操作系统课程的学生提交采集、实验过程清洗、源码差异审阅、AI/人工贡献识别和诚信审核工具集。

## 项目状态

本仓库已归档，不再进行更新。`OS-Lab-Score-工具最终版-20260922.zip` 是本地工具阶段的最终打包版本，包含学生数据抓取、实验过程清洗、代码差异报告、AI/人工贡献识别和诚信审核五个工具。

后续将把这五个工具的全部能力迁移到新的文件夹和新仓库，为服务器端开发、部署和维护做准备。新仓库启用后，后续开发将在新仓库中进行。

## 工作流

1. `学生数据抓取工具/` 从课程提交服务器下载最新归档到 `操作系统实验数据记录/`。
2. `学生操作系统实验过程清洗工具/` 重放终端录像并写入 `操作系统实验数据记录-已清洗/`。
3. `学生操作系统实验过程清洗工具/代码差异报告工具/` 按当前提交和源码指纹复用结果，只对失效的学生/Lab 单元重新生成源码差异报告。
4. `学生操作系统实验过程清洗工具/AI人工贡献识别工具/` 按需读取过程和差异材料，生成贡献证据。
5. `诚信判别系统/` 只读这些材料，生成教师复核报告和运行日志。

所有脚本都以自身所在位置定位仓库根目录，因而可在 Linux 服务器任意工作目录启动。输入、输出和本地依赖均可通过各工具的命令行参数覆盖。

## 目录

```text
操作系统实验数据记录/              原始提交数据（本工具写入）
操作系统实验数据记录-已清洗/       清洗与审阅产物（本工具写入）
学生数据抓取工具/                  SFTP 抓取入口
学生操作系统实验过程清洗工具/      过程清洗、差异与贡献识别工具
诚信判别系统/                      教师诚信审核工具
xv6-ai-labs-km-无答案/             本地参考基准，不纳入 Git
公共依赖/                          本地缓存依赖，不纳入 Git
```

具体安装、参数和输入约定请阅读相应工具目录的 `README.md`。终端清洗默认采用混合模式和 `min(12, 可用 CPU 核数)` 个 Python 多进程 worker；需要全量逐帧复核时运行 `python3 学生操作系统实验过程清洗工具/实验过程清洗工具/replay_term_qa.py --replay-mode exact`，也可在混合批次中重复 `--exact-recording <录像ID>`。录像级缓存位于输出根 `.replay-cache/`，每次扫描只保留当前分析器版本和当前源中的条目，不删除原始数据或正式报告。

终端证据分为 E1（pyte 屏幕状态、精确帧和录像字节范围）与 E2（标注行号、关联置信度和时间语义的“采集日志佐证”）；E2 不会冒充屏幕证据。依赖仅为 Python、`pyte`（LGPL-3.0-or-later）和 `wcwidth`，不需要 `python-isal` 或 `indexed_gzip`。

代码差异工具的结构化缓存位于 `操作系统实验数据记录-已清洗/.lab-diff-cache/`，缓存键包含学生学号、当前归档 SHA-256、Lab 和比较规则。源码指纹未变化时会复用差异结果，不重新调用 Git；只修改一个学生的一个 Lab 时只重算该单元，基准的某个 Lab 变化时只使该 Lab 的学生失效。正式报告仍同时出现在 `按人分类/` 和 `按Lab分类/`，重复运行未变化输入时 Markdown/JSON 字节保持一致。报告、镜像和所有权清单按事务顺序发布；清单或镜像写入失败会恢复旧的正式产物，首次发布失败不会留下未登记报告。输入不完整或来源无法确认时保留旧报告并返回诊断，不按姓名猜测归属，也不会清理其他学生的缓存。详细参数、`--force`、清理规则和失败语义见[代码差异报告工具说明](学生操作系统实验过程清洗工具/代码差异报告工具/README.md)。

## 安全与部署

- 不要提交学生原始数据、测试数据、运行日志、`.env` 或 `*.local` 文件。
- 服务器凭据及 `NVIDIA_API_KEY` 只通过系统环境变量或密钥管理器注入。
- `公共依赖/` 与 `xv6-ai-labs-km-无答案/` 是本地目录；请按各工具 README 安装 Python 依赖并准备 xv6 基准。
- 诚信审核报告是教师复核材料，不是自动处分、评分或违规结论。
