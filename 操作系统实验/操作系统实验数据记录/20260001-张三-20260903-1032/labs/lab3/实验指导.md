## 基础知识

### 进程地址空间

xv6 中每个进程有独立的用户页表，描绘一段连续的用户地址空间 `[0, sz)`。`sz` 是 `struct proc` 的字段，记录当前用户地址空间大小（字节）。

```text
用户地址空间 [0, sz)
┌─────────────────────────────────────┐ 0
│  用户代码段、数据段、栈等             │
│                                     │
├─────────────────────────────────────┤ sz（当前堆顶）
│  尚未映射的虚拟地址（访问触发 fault） │
│                                     │
└─────────────────────────────────────┘
```

`sz` 把"已映射"和"未映射"分开。扩展地址空间就是抬高 `sz`，收缩就是降低 `sz`。

### `sbrk` 与 `brk`

xv6 原生提供 `sbrk(n)`，参数 `n` 是字节数（增量语义）：

- `n > 0`：堆顶抬高 n 字节，扩展地址空间
- `n < 0`：堆顶降低 n 字节，收缩地址空间
- 返回值是抬高前的旧 sz

Linux 的 `brk(addr)` 是绝对值语义：

- `addr > 0`：把堆顶设到 addr
- `addr == 0`：查询当前堆顶，不修改

oscomp 测例按 Linux `brk` 语义编写。本 lab 的 `sys_brk` 需要实现查询和设置两种语义。

### `growproc` 与 `uvmalloc` / `uvmdealloc`

`kernel/proc.c` 中的 `growproc(int n)` 是改变进程地址空间大小的统一入口：

```c
int growproc(int n) {
    uint sz;
    struct proc *p = myproc();
    sz = p->sz;
    if(n > 0) {
        if((sz = uvmalloc(p->pagetable, p->kpagetable, sz, sz + n)) == 0)
            return -1;
    } else if(n < 0) {
        sz = uvmdealloc(p->pagetable, p->kpagetable, sz, sz + n);
    }
    p->sz = sz;
    return 0;
}
```

- `n > 0`：调 `uvmalloc` 分配新物理页、建立页表映射、抬高 sz
- `n < 0`：调 `uvmdealloc` 解除映射、释放物理页、降低 sz
- `n == 0`：什么都不做

`uvmalloc` 内部对每一页调用 `kalloc` 分配物理页、`mappages` 建立虚拟→物理映射，并把页清零。`uvmdealloc` 走相反路径，最终调 `uvmunmap` + `kfree`。

理解这条链路后，`sys_brk` / `sys_mmap` / `sys_munmap` 三者都可以通过复用 `growproc` 实现。

### `mmap` 与匿名映射

Linux 的 `mmap` 功能复杂：

- 文件映射：把文件的一段映射到进程地址空间
- 匿名映射：分配一段无文件背景的内存（典型用法类似 malloc）
- 指定地址或由内核选地址
- 权限、标志、共享/私有等多种选项

完整 mmap 需要 VMA（Virtual Memory Area）管理，工程量大。本 lab 主线只做**匿名映射简化版**：复用 `growproc` 在地址空间末尾追加一段区域，忽略 `prot` / `flags` / `fd` / `offset` 参数。完整 mmap 属于 CP⑤ 支线，可跳过。

### `munmap` 与简化版解除

Linux 的 `munmap(addr, length)` 解除指定地址段的映射。完整实现需要 VMA 管理，支持任意地址。

本 lab 主线只做**简化版**：复用 `growproc(-length)` 在地址空间末尾收缩。这相当于"逆序解除最近 mmap 的那块"，只对栈式追加/收缩有效。完整 munmap 属于 CP⑤ 支线。

### 关键参考实现

#### `sys_sbrk`（同文件约 90 行）

```c
uint64 sys_sbrk(void) {
    int addr;
    int n;
    if(argint(0, &n) < 0)
        return -1;
    addr = myproc()->sz;          // 记录旧 sz
    if(growproc(n) < 0)
        return -1;
    return addr;                   // 返回旧 sz
}
```

这是 xv6 原生的"增量语义"实现。`sys_brk` 在此基础上改造为"绝对值语义 + 查询语义"。

#### `growproc`（`kernel/proc.c` 约 316 行）

见"基础知识"小节源码。它把正负 `n` 分别走 `uvmalloc` 和 `uvmdealloc` 路径，最终更新 `p->sz`。

### 三个 CP 在 `sysproc.c` 末尾

```text
sysproc.c 末尾：
    sys_brk     ← CP① 占位 return -1
    sys_mmap    ← CP② 占位 return (uint64)-1
    sys_munmap  ← CP③ 占位 return -1
```

三个 CP 都通过复用 `growproc` 实现。本 lab 的本质是理解"绝对值/增量"和"扩展/收缩"在地址空间操作上的关系。

### 任务2：CP① 实现 `sys_brk`

#### 步骤1：阅读 `sys_sbrk`（约 90 行）

`sys_sbrk` 用 `argint(0, &n)` 取增量参数，记旧 sz，调 `growproc(n)`，返回旧 sz。

#### 步骤2：理解 `brk` 的两种语义

`brk(addr)` 根据 `addr` 取值有两种行为：

- `addr == 0`：查询语义，返回当前 `myproc()->sz`，不修改地址空间
- `addr > 0`：设置语义，把堆顶设到 `addr`，相当于 `growproc(addr - myproc()->sz)`

实现时需要分这两个分支。

#### 步骤3：阅读 `sys_brk` 的参数读取（约 184 行）

```c
uint64 sys_brk(void) {
    uint64 addr;
    if(argaddr(0, &addr) < 0)
        return -1;
    // todo（CP①）
    return -1;
}
```

参数已经通过 `argaddr(0, &addr)` 取到，分支逻辑由学生补全。

#### 步骤4：实现 `sys_brk`

按步骤2的两个分支补全实现。查询分支返回 `myproc()->sz`；设置分支计算 `n = addr - sz`，调 `growproc(n)`，返回新 sz。

实现完成后重新构建运行 `mmaptest`，期望第一行输出形如：

```text
brk(0) = 0x<某合法地址>
```

而不是 `brk(0) failed`。

### 任务3：CP② 实现 `sys_mmap`

#### 步骤1：理解匿名映射简化模型

本 lab 的 mmap 简化策略：忽略 `prot` / `flags` / `fd` / `offset`，把 `length` 字节当作地址空间末尾追加的新区域。扩展用 `growproc(length)`，返回值是扩展前的旧 sz（即新区域的起始地址）。

#### 步骤2：阅读 `mmap` 的参数顺序

`mmap` 用户态原型：

```c
uint64 mmap(void *addr, int length, int prot, int flags, int fd, int offset);
```

第一个参数 `addr` 在简化版中忽略（不指定起始地址，由内核决定）。第二个参数 `length` 是要映射的字节数，简化版只需读取这一项。

`sys_mmap` 的参数可以用 `argint(1, &length)` 取到（注意是第二个参数，下标为 1）。

#### 步骤3：实现 `sys_mmap`

实现思路：

1. 用 `argint(1, &length)` 取 `length`
2. 记录旧 sz：`uint64 old = myproc()->sz;`
3. 调 `growproc(length)` 扩展地址空间
4. 失败返回 `(uint64)-1`，成功返回 `old`（新映射区域的起始地址）

实现完成后重新构建运行 `mmaptest`，期望前几行输出形如：

```text
brk(0) = 0x<...>
mmap returned 0x<旧 sz>
mmap read/write OK
```

#### 步骤4：检查地址对齐

`uvmalloc` 内部对地址做页对齐处理。即使 `length` 不是 4KB 整数倍，实际扩展仍按整页计算。这一点不需要在 syscall 层处理，`growproc` 已经处理。

### 任务4：CP③ 实现 `sys_munmap`

#### 步骤1：理解简化版 munmap 语义

简化版策略：复用 `growproc(-length)` 在地址空间末尾收缩。这相当于"撤销最近一次 mmap"。

完整 munmap 支持任意地址解除，需要 VMA 管理；本 lab 主线不实现完整版。

#### 步骤2：阅读 `sys_munmap` 的参数

用户态原型：

```c
int munmap(void *addr, int length);
```

简化版忽略 `addr`（只支持末尾收缩），只用 `length`。参数可以用 `argint(1, &length)` 取到。

#### 步骤3：实现 `sys_munmap`

实现思路：

1. 用 `argint(1, &length)` 取 `length`
2. 调 `growproc(-length)` 收缩地址空间
3. 失败返回 -1，成功返回 0

```bash

make fs
make run
```

在 shell 中执行 `mmaptest`，期望输出：

```text

mmap returned 0x<...>
mmap read/write OK
lab3 test passed
```

看到 `lab3 test passed` 即通过。

### 现象分层定位

| 故障层 | 现象 | 排查方向 |
|--------|------|----------|
| `brk(0)` 层 | `brk(0) failed` 或返回值明显错误 | CP①：查询分支是否直接返回 `myproc()->sz`？ |
| `brk(addr)` 层 | 设置语义下行为异常 | CP①：`growproc(addr - sz)` 的增量计算是否正确？ |
| `mmap` 返回层 | `mmap failed` 或返回 -1 | CP②：是否调了 `growproc`？返回值是否是旧 sz？ |
| `mmap` 读写层 | `mmap read/write FAILED` | CP②：`growproc` 内部没建好映射，或返回地址错（返回了新 sz 而不是旧 sz） |
| `munmap` 层 | `munmap failed` | CP③：`growproc(-length)` 是否被调用？length 是否合法？ |
| 系统崩溃 | mmap 后 panic | 返回地址错（可能返回新 sz 而非旧 sz），导致用户访问越界 |

## 常见问题（FAQ）

| 现象 | 原因 / 解决 |
|------|------------|
| `brk(0) failed` | CP① 查询分支没实现，仍返回 -1 |
| `brk(0)` 返回值是 0 | CP① 没取到 `myproc()->sz`，可能写成 `return 0;` |
| `mmap failed` | CP② 没调 `growproc`，或 `argint` 取的参数下标错 |
| `mmap read/write FAILED` | CP② 返回了新 sz 而非旧 sz，导致用户访问越界；或 `growproc` 内部映射没建好（少见，检查 uvmalloc） |
| `mmap` 后 panic | 同上，返回地址错 |
| `munmap failed` | CP③ 没调 `growproc(-length)`，或参数下标错 |
| `mmaptest` 第二次跑崩溃 | `munmap` 实现错误，破坏了进程的页表结构 |

## 思考题（可选）

下列题目用于加深理解：

1. **`sbrk(n)` 和 `brk(addr)` 在语义上有什么本质区别？** 提示：增量 vs 绝对值。如何用一个实现另一个？
2. **简化版 `mmap` 为什么返回旧 sz 而不是新 sz？** 提示：用户程序需要拿到新区域的起始地址，新 sz 是结束地址。
3. **简化版 `munmap` 只支持末尾收缩，为什么不能解除任意地址？** 提示：完整实现需要 VMA 管理地址区间，本 lab 主线跳过。
4. **`growproc(0)` 会做什么？对 `sys_brk` 的查询分支有影响吗？** 提示：看 growproc 实现。
5. **完整 mmap 为什么要区分文件映射和匿名映射？两者底层有什么本质不同？** 提示：匿名映射没有文件 backing，文件映射需要绑定 inode 和 offset。
