## 三、硬件最低配置

以下配置针对**你本地电脑（宿主机）**，因为 VMware 虚拟机 + 虚拟化 + 交叉编译同时运行会占用较多资源。

| 项目       | 最低要求                      | 建议配置                  | 说明                                                         |
| ---------- | ----------------------------- | ------------------------- | ------------------------------------------------------------ |
| CPU        | x86_64，4 核，支持硬件虚拟化  | 8 核及以上                | 必须支持虚拟化：Intel VT-x 或 AMD-V                          |
| 内存       | 8 GB                          | 16 GB 及以上              | 虚拟机分配 4 GB 后，宿主机还要留出系统余量                   |
| 磁盘       | 60 GB 可用空间                | 120 GB SSD                | 镜像 + 虚拟机磁盘 + 工具链约需 40~60 GB                      |
| 操作系统   | Windows 10/11 64 位，或 Linux | Windows 11 / Ubuntu 24.04 | macOS：Intel 芯片可用 VMware Fusion；M 系列芯片不支持，请用云端方案或 UTM |
| 网络       | 能正常访问外网                | 宽带                      | 下载镜像、安装工具、调用 Claude 都需要                       |
| 虚拟化开关 | BIOS/UEFI 中开启 VT-x/SVM     | —                         | 不开启则 VMware 无法创建虚拟机                               |

### 怎么确认电脑支持虚拟化

**Windows**：任务管理器 → 性能 → CPU → 查看"虚拟化"一栏是否为"已启用"。

**Linux**：

```bash
grep -E 'vmx|svm' /proc/cpuinfo | head -1
```

有输出即支持（`vmx` 是 Intel，`svm` 是 AMD）。若显示未启用，重启进 BIOS/UEFI，在 CPU 设置里打开 Intel Virtualization Technology 或 SVM Mode。

> 常见误判：内存只有 4 GB 的电脑装 VMware 后"虚拟机开不动"或"宿主机卡死"。这不是 VMware 的问题，是硬件不达标。请按上表升级，或改用云端方案。

## 五、本地环境搭建

> 本地环境搭建对应第一章的**方案一**和**方案二**。两种方案最终都得到一个装好全部工具的 Ubuntu 虚拟机；方案二导入预装镜像后，可跳过 5.5、5.6 的工具链与 QEMU 安装（镜像已预装）。

### 5.1 第 1 步：安装 VMware Workstation Pro

#### 版本说明

课程要求 **VMware Workstation Pro 17.5.1 及以上**。该版本对个人使用免费（需要免费注册一个 Broadcom 账号后从官方渠道下载），安装后无需付费密钥。

如已安装其他版本：

- 17.5.1 及以上：可直接使用
- 17.5.0 及以下：建议升级到 17.5.1

#### 安装步骤

1. 获取 VMware Workstation Pro 17.5.1 的安装包（`VMware-workstation-full-17.5.1-23298084.exe`，约 600 MB），二选一：
   - **课程网盘（推荐）**：https://pan.baidu.com/s/15BB3tYyUNNotWEnkEqVmfQ?pwd=1234 （提取码：`1234`）
   - **VMware 官方渠道**：需免费注册 Broadcom 账号后从官网下载（个人使用免费，无需密钥）
2. 双击安装包，按默认选项一路下一步。
3. 安装过程中可勾选"增强型虚拟键盘驱动程序"（默认即可）。
4. 安装完成后重启电脑。
5. 首次启动 VMware 时会询问是否输入许可证，选择个人使用即可（17.5.1 个人版免费，无需密钥）。

#### 安装前必须确认

- [ ] 第三章硬件表中"虚拟化"已开启；
- [ ] Windows 的"Windows 虚拟机监控程序平台"和"虚拟机平台"功能未冲突（若开启过 Hyper-V/WSL2，遇到 VMware 无法启动时按第七章常见问题处理）。

### 5.2 第 2 步：准备 Ubuntu 虚拟机

#### 两种方式（任选其一）

| 方式            | 说明                                                         | 适用场景               |
| --------------- | ------------------------------------------------------------ | ---------------------- |
| 导入课程镜像    | 上课后发布课程网盘，提供 `.ova` 镜像，VMware 直接导入，环境已配好 | 推荐新手               |
| 全新安装 Ubuntu | 自己新建虚拟机并安装 Ubuntu 24.04，再按本手册 5.3~5.6 手动装环境 | 想完整体验环境搭建过程 |

#### 导入课程镜像（推荐）

1. 上课的时候，会提供网盘链接。

2. 从移动硬盘下载 `.ova` 镜像文件。双击 `.ova` 文件，VMware 自动弹出导入向导；或 VMware 菜单 `文件 → 打开` 选择该文件。

3. 命名虚拟机（如 `xv6-lab`），选择存储位置（磁盘充足的分区）。

4. 硬件配置建议：

   | 项目       | 建议值      |
   | ---------- | ----------- |
   | 处理器     | 2 核及以上  |
   | 内存       | 4 GB 及以上 |
   | 网络适配器 | NAT（默认） |

5. 点击完成，等待导入（约 5~15 分钟）。

6. 启动虚拟机，用教师提供的账号密码登录。

> 若导入后虚拟机内无法联网（网络图标问号），处理：`编辑 → 虚拟网络编辑器 → 更改设置 → 重置网络`。

#### 全新安装 Ubuntu 24.04（可选）

若选择自己装（先从官网下载 Ubuntu 24.04 ISO 镜像：https://ubuntu.com/download/alternative-downloads）：

1. VMware 菜单 `文件 → 新建虚拟机` → 典型。
2. 选择**「安装程序光盘映像文件(iso)」**，浏览并选中刚下载的 Ubuntu 24.04 ISO 文件。
3. 按向导填写用户名/密码、虚拟机名称和存储位置，分配 2 核 / 4 GB 内存 / 40 GB 磁盘。
4. 点击完成后 VMware 会从 ISO 启动，进入 Ubuntu 安装向导，按提示完成安装。
5. 安装完成后打开终端（`Ctrl+Alt+T`），按 5.3~5.6 手动安装工具。

### 5.4 第 4 步：安装 Claude Code

Claude Code 是本课程 AI 辅助学习模式的核心工具。在 `labN/` 目录下启动后，它会自动按课程约束引导你完成实验。

> **推荐路径**：直接运行课程一键脚本（见下文"配置 API 与中转地址"方式一），它会自动完成 Node.js 安装、Claude Code 安装和密钥配置。下面是手动拆解步骤，供想自己控制每一步的读者参考。

#### 安装 Node.js（≥ 18，推荐 22 LTS）

```bash
node -v   # 检查是否已有 Node；若 ≥ v18 可跳过本步
```

如果没有，用 **nvm** 安装 Node 22 LTS（比 apt 仓库自带的版本新，且按用户安装、不污染系统、可随时切换）：

```bash
curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash
export NVM_DIR="$HOME/.nvm"; [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
nvm install 22 && nvm use 22
node -v   # 应输出 v22.x
```

> 为什么不用 `apt` 装 Node：Ubuntu 24.04 仓库里的 Node 版本偏旧，且升级麻烦；Claude Code 要求 Node ≥ 18，推荐 22 LTS。

#### 安装 Claude Code

```bash
npm install -g @anthropic-ai/claude-code

# 验证
claude --version
```

#### 配置 API 与中转地址（两种方式任选其一）

**方式一：课程一键脚本（推荐）**

```bash
curl -O "https://kuafuai.art/claude_code_env.sh" && bash ./claude_code_env.sh
```

脚本自动完成 6 步：

1. 检查/安装 Node.js（nvm 装 Node 22 LTS，要求 ≥ 18）；
2. 安装 Claude Code（`npm install -g @anthropic-ai/claude-code`）；
3. 初始化 Claude Code 状态，跳过首次启动的交互向导；
4. 引导你输入**中转地址**与**API Key**（输入时不回显，不落 shell 历史）；
5. 从中转站的 `/v1/models` 拉取可用模型列表，用 ↑/↓ 选择要用的模型；
6. 选择是否使用 **1m 长上下文版本**，然后把配置写入 `~/.claude/settings.json`。

配置完成后直接运行 `claude` 即可，**无需每次 export**。

**方式二：手动配置（不想跑脚本时）**

安装完成后，编辑 `~/.claude/settings.json`（不存在就新建），写入：

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "sk-...",
    "ANTHROPIC_BASE_URL": "https://<模型url>",
    "ANTHROPIC_MODEL": "<模型名>",
    "ANTHROPIC_SMALL_FAST_MODEL": "<模型名>",
    "API_TIMEOUT_MS": "3000000",
    "CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC": "1"
  }
}
```

字段说明：

- `ANTHROPIC_AUTH_TOKEN`：API Key 用 **token 方式**传入，Claude Code 会自动读取，**不要用 `export ANTHROPIC_API_KEY` 写进环境变量**——既不持久（新终端失效）、还会留在 shell 历史里；
- `ANTHROPIC_BASE_URL`：中转 API 地址，由课程教师统一提供（或使用大模型厂商密钥）；
- `ANTHROPIC_MODEL` / `ANTHROPIC_SMALL_FAST_MODEL`：主模型与轻量模型，一般填同一个模型名（脚本第 5 步会从 `/v1/models` 自动列出可用模型，选 1m 版本时模型名后带 `[1m]` 后缀）；
- `API_TIMEOUT_MS`：请求超时（毫秒）。xv6 编译/跑测试耗时长，默认超时容易中断，这里设为 3000000（50 分钟）；
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`：关闭非必要网络流量。

#### 网络注意事项（重要）

Claude 官方 API 在国内访问可能不稳定。如果遇到连接失败或超时，确认：

1. 中转地址是否正确写入 `~/.claude/settings.json`（不是 shell 里 export 的临时变量）；
2. 中转地址和模型名是否与教师提供的一致（脚本方式会自动拉取模型列表，不易填错）；
3. 仍超时的话，检查 `API_TIMEOUT_MS` 是否被覆盖为小值。

#### 验证 Claude Code 可用

```bash
cd lab0
claude
```

进入后输入一句"你好"，能正常回复即表示配置成功。输入 `/exit` 退出。

### 5.5 第 5 步：安装 RISC-V 交叉编译工具链

xv6 内核运行在 RISC-V 架构上，但我们是在 x86_64 的电脑上编译它，所以需要交叉编译器。

#### 安装

```bash
# 检查是否已装
riscv64-unknown-elf-gcc --version

# 未安装则用 apt 安装
sudo apt install gcc-riscv64-unknown-elf
```

#### 确认 TOOLPREFIX 与工具链匹配

打开实验仓库 `lab0/Makefile`，找到：

```makefile
TOOLPREFIX	:= riscv64-unknown-elf-
# TOOLPREFIX	:= riscv64-linux-gnu-
```

- 装的 `riscv64-unknown-elf-gcc` → 保持默认即可；
- 装的 `riscv64-linux-gnu-gcc`（`sudo apt install gcc-riscv64-linux-gnu`）→ 把前缀改为 `riscv64-linux-gnu-` 并注释掉原行。

`TOOLPREFIX` 与工具链不匹配会直接编译失败。

#### 验证

```bash
riscv64-unknown-elf-gcc --version
riscv64-unknown-elf-ld --version
```

两条命令都能输出版本号即可。

> GCC 13 兼容说明：Ubuntu 24.04 的 `riscv64-unknown-elf-gcc` 通常是 GCC 13，对 `sh.c:runcmd()` 会报 `infinite recursion detected` 警告。本课程仓库已在 Makefile 的 `CFLAGS` 中加入 `-Wno-error=infinite-recursion`，无需处理。若看到 `LOAD segment with RWX permissions` 的链接警告，那是警告不是错误，只要最终生成 `target/kernel` 即可继续。

## 七、常见问题

| 现象                                               | 原因 / 解决                                                  |
| -------------------------------------------------- | ------------------------------------------------------------ |
| VMware 无法启动虚拟机                              | BIOS 未开启虚拟化，或与 Hyper-V/WSL2 冲突。开启 VT-x/SVM 后重启；Windows 上可尝试关闭"虚拟机监控程序平台"或改用 VMware 17.5.1 |
| 虚拟机内无法联网（网络图标问号）                   | VMware 虚拟网络适配器映射错位。`编辑 → 虚拟网络编辑器 → 更改设置 → 重置网络`，重启虚拟机 |
| 虚拟机运行卡顿                                     | 宿主机内存不足（需 8 GB 以上）；给虚拟机降到 2 核/4 GB；关闭宿主机其他大程序 |
| `riscv64-unknown-elf-gcc: command not found`       | 工具链未安装，执行 `sudo apt install gcc-riscv64-unknown-elf` |
| `make build` 报 `unrecognized command-line option` | 工具链版本与内核期望不匹配，或 TOOLPREFIX 不对，检查 `Makefile` |
| `make build` 报 `infinite recursion detected`      | GCC 13 兼容性诊断；确认 Makefile 含 `-Wno-error=infinite-recursion` |
| `qemu-system-riscv64: command not found`           | QEMU 未安装，执行 `sudo apt install qemu-system-misc`        |
| `make fs` 报 `mount: operation not permitted`      | 没用 sudo，或 `/mnt` 被占用。先 `sudo umount /mnt` 再重试    |
| `make run` 后看到 `-> / $` 但输入无反应            | QEMU 8.2/OpenSBI 1.3 与旧控制台输入不兼容；当前仓库已修复，退出旧 QEMU 后重新 `make run` |
| `claude` 连接失败或超时                            | 网络问题。配置代理或按 5.4 节使用教师提供的中转地址           |
| `npm` 命令找不到                                   | Node.js 未安装或 PATH 未生效，重开终端或重新安装 Node 20     |
