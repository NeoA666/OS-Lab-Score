● exec() 的作用一句话概括：用磁盘上的一个新程序，替换掉当前进程的用户态内存镜像
  。注意它不创建新进程——进程还是那一个（PID 不变），只是"灵魂换了"。

  一、它在 xv6 里是个系统调用，分三层

  用户态:  sh.c:178  exec(argv[0], argv)
              ↑ user.h:18 声明, usys.pl:26 生成 usys.S → ecall 指令陷入内核
  内核分发: syscall.c:127  [SYS_exec] sys_exec   ← 函数指针表
  实际实现: sysproc.c:17   sys_exec()  →  kernel/exec.c:44  exec()

  sysproc.c:17 的 sys_exec() 只做参数搬运：把用户空间传进来的 path 和 argv[]
  数组（argstr/fetchaddr/fetchstr，sysproc.c:23-43）复制到内核自己的缓冲区，然后  才调用真正的 exec()。

  这层搬运不是多余的。内核不能直接解引用用户传进来的指针——用户可能传一个内核地址  或者非法地址。所有 arg* / copyin / copyout 都会校验地址范围。

  二、exec() 内部做的五件事（kernel/exec.c:44）

  1. 打开文件、校验 ELF（exec.c:66-78）
  ename(path) 拿到目录项，读 ELF 头，检查 elf.magic != ELF_MAGIC。

  2. 遍历 program header，按段装载（exec.c:83-100）
  for(i=0, off=elf.phoff; i<elf.phnum; i++, off+=sizeof(ph)){
      if(ph.type != ELF_PROG_LOAD) continue;
      if((sz1 = uvmalloc(pagetable, kpagetable, sz, ph.vaddr + ph.memsz)) == 0)
  goto bad;
      if(loadseg(pagetable, ph.vaddr, ep, ph.off, ph.filesz) < 0) goto bad;
  }
  uvmalloc
  分配物理页并建立映射，loadseg（exec.c:20）把磁盘上的代码/数据读进去。注意
  memsz（内存占用）通常大于 filesz（文件占用）——多出来的部分是 .bss，零初始化。

  3. 建立用户栈（exec.c:108-117）
  if((sz1 = uvmalloc(pagetable, kpagetable, sz, sz + 2*PGSIZE)) == 0) goto bad;
  uvmclear(pagetable, sz-2*PGSIZE);   // 清掉 PTE_U → guard page
  sp = sz;
  stackbase = sp - PGSIZE;
  分配两页，但第一页用 uvmclear 抹掉用户权限位，变成守护页——栈溢出时会触发 page
  fault，而不是静默踩坏别的内存。

  4. 压参数进栈（exec.c:119-144）
  先逐个压入参数字符串，再压 argv[] 指针数组。sp -= sp % 16 是 RISC-V ABI 要求的  16 字节栈对齐。最后：
  p->trapframe->a1 = sp;   // main 的 argv

  5. 提交：切换页表（exec.c:152-164）
  oldpagetable = p->pagetable;
  p->pagetable = pagetable;          // ← 原子切换点
  p->sz = sz;
  p->trapframe->epc = elf.entry;     // 新程序入口
  p->trapframe->sp  = sp;
  proc_freepagetable(oldpagetable, oldsz);
  return argc;                        // 经由 a0 返回给 main

  三、两个容易忽略但很重要的设计

  ① 失败必须原子（exec.c:166-178）

  整个过程中，新地址空间是在一边慢慢搭起来的，旧的原封不动。只有全部成功了才在
  exec.c:155 换指针。任何一步失败都跳到 bad:，只释放新分配的资源：

  bad:
    if(pagetable) proc_freepagetable(pagetable, sz);

  所以 exec 返回 -1
  时，进程的旧映像完好无损，还能继续执行、打印错误。这就是为什么 sh.c:178
  可以直接在 exec 返回后往下走：

  exec(ecmd->argv[0], ecmd->argv);
  // 能走到这说明 exec 失败了
  printf("exec %s failed\n", ...);
  exit(1);

  ② 文件描述符表不换

  exec 只替换内存镜像，p->ofile[] 保持不变。这正是 shell
  重定向能工作的原因：sh.c 在 fork 出的子进程里先 close(0); open(...)，再调用
  exec——新程序继承了已经改好的 fd。

  四、和你上个问题的呼应：exec 成功后"不返回"

  exec 成功时，return argc 这条语句返回的是新程序 main
  的第一次执行，而不是回到调用 exec 的下一行。机制就是 trapframe->epc 被改成了
  elf.entry、sp 被改成了新栈——当这个进程下次从内核态返回用户态时，sret
  跳到的就是新程序的入口。

  对比一下：
  - fork() 返回两次（父一次子一次，都在调用点）
  - exec() 成功时不返回到调用点，直接进入新程序；失败时返回一次 -1

  五、这个 k210 移植版的特殊之处

  原版 xv6-riscv 只有一个用户页表，内核跑在直接映射（satp
  不切）。这个版本改成了内核也有页表，所以你能看到处处是成对出现的 pagetable /
  kpagetable（exec.c:52-53）：

  if((kpagetable = (pagetable_t)kalloc()) == NULL) return -1;
  memmove(kpagetable, p->kpagetable, PGSIZE);   // 复制内核映射
  for (int i = 0; i < PX(2, MAXUVA); i++)
      kpagetable[i] = 0;                         // 但清掉用户空间部分

  结尾还多了两行硬件操作（exec.c:161-163）：
  w_satp(MAKE_SATP(p->kpagetable));
  sfence_vma();          // 刷新 TLB，否则旧映射还在缓存里
  kvmfree(oldkpagetable, 0);

  sfence_vma 是必须的——改了页表不刷 TLB，CPU 可能还在用旧的地址翻译。

  ---
  一句话总结：exec 是"先在新地址空间里把程序搭好、栈铺好、把 argc/argv
  安排好，最后一次性把页表指针换掉"的原子操作。fork + exec
  的组合才等于其它系统里的 CreateProcess / posix_spawn。
