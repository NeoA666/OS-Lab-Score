先给个直觉："virt" 不是地球上真实存在的某块板子，而是 QEMU

它没有实体，纯粹是用软件拼出来的。

它长什么样（几个部件）

看 Makefile 里 run 那一行，其实就是在"点菜"告诉 QEMU 这台假电脑要哪些零件：

             参数                      给这台假电脑配的零件
 -smp 2                        2 个 RISC-V CPU 核
 -m 128M                       128 MB 内存（一段连续地址）
 -drive ... virtio-blk-device  一块"硬盘"，挂的是你的 fs.img
 -nographic                    一个串口，把屏幕输出直接打到你的终端
 -bios default                 一段开机固件 OpenSBI

所以它就是一个「2 核 CPU + 128M 内存 + 一块虚拟硬盘 + 一个串口」的裸机小电脑——
没有显卡、没有鼠标、没有真实硬盘，简到不能再简，够操作系统跑起来就行。

关键：你其实已经"见过"它了

你之前 make run 时，屏幕最上面那堆 Platform ... 的字，就是 OpenSBI
开机后给这台假电脑报的身份证：

Platform Name         : riscv-virtio,qemu   ← 名字就叫 "virt"
Platform HART Count   : 2                    ← 2 个核
Platform Timer Device : aclint-mtimer @ 10000000Hz
Platform Console Device: uart8250            ← 串口
Firmware Base         : 0x80000000           ← OpenSBI 装在内存 0x80000000

Platform HART Count : 2 对应 -smp 2，uart8250 对应 -nographic
那个串口。你在终端里看到的这些，就是这台假电脑在"自我介绍"。

为什么 QEMU 要造一台假的，而不是模拟真板子

因为真实的 RISC-V 板子五花八门，每块板子的内存地址、外设都不一样。写操作系统如
果每块真板子都适配一遍，累死了。QEMU 就造一台最简、最标准的
virt，大家都拿它当通用靶子——你在上面写对了，再移植到真板子（比如 xv6-k210
原本要跑的那个 K210 芯片）就容易了。

### Turn 11

#### User

软件的特权也需要靠硬件实现吧？硬件特权级最高？

#### Claude

对，方向对了，但"硬件特权级最高"这个说法要稍微拧一下——不然会卡在一个错误的图景
里。

特权级确实是硬件实现的。 关键点：CPU
内部有一个**"当前处于哪个特权级"的状态**（RISC-V 里体现在 mstatus 等 CSR
里），硬件根据这个状态来决定——某条指令能不能执行、某块地址能不能访问。软件不能
"自己给自己升级"，否则用户程序改个变量就变成内核了，那整个保护机制就形同虚设。
所以特权必须由硬件强制，软件没得选。

但"高"不是硬件和软件在比高低。 RISC-V
一共定义了三个特权级，它们全由硬件强制，只是等级不同：

- M 态（Machine，机器态）——最高。跑固件，也就是这里 lab0 会遇到的 SBI。
- S 态（Supervisor，监管态）——中间。跑操作系统内核，xv6 就运行在这一层。
- U 态（User，用户态）——最低。跑普通用户程序。

所以注意一个你可能没意识到的点：你的 xv6 内核本身不是最高特权级，它运行在 S
态；它头顶上还有 M 态的 SBI 压着。

方向对了，但有一个词要帮你拧精确：不是"申请权限"，是请它代办。

区别在哪？如果内核"申请到权限"，意思是内核获得了能力，之后自己就能关机了。但实
际不是——内核自始至终都干不了关机、设时钟这些事，它们只属于 M
态。内核真正能做的是：执行一条 ecall 指令，主动把 CPU 从 S 态"抬"进 M 态，请
SBI 固件替它把这件事做完，再把结果带回来。做完之后内核还是 S
态，什么都没获得，只拿了个结果。

所以 lab0 思考题"为什么用 SBI"背后那一步是：SBI 不是发权限，是提供服务。

一次了：

- 用户程序干不了的事 → 请 S 态内核代办，这叫系统调用（syscall）
- 内核干不了的事 → 请 M  Jump to bottom (ctrl+End) ↓

里有句话叫"哈希链在第 X 行断裂"，指的就是它。

先讲"哈希"是什么

哈希 = 一份数据的"指纹"。 把任何一段内容（一行日志、一个文件）丢进一个算法，会
算出一串固定长度的乱码（比如 1c1a9377...588e）。它有俩特性：

1. 同样的内容，算出来永远一样；
2. 内容哪怕只改一个字符，算出来的指纹就完全变样。

所以它很像指纹：靠它就能判断"这份东西有没有被人动过"。

再讲"链"是怎么扣起来的

记录你实验过程的日志
events.jsonl，是一行一条往下记的。每条记录里都存了两个字段：

- prev：上一条记录的指纹
- h：本条记录自己的指纹

就像一条铁链，每一环都"咬住"上一环：

第1条 → 第2条（第2条里记着第1条的指纹）→ 第3条（记着第2条的指纹）→ …

它有什么用

有了这条链，谁要是偷偷改或删掉中间某条记录，立刻就露馅：

- 假设你把第 3 条删了，那么第 4 条里记的"上一条指纹"（本该是第 3
条的）就对不上了 → 链断了
- 检查程序（就是提交时跑的那个）一验，就能发现"第 3 条和第 4
条之间对不上"，报出"哈希链断裂"

为什么要搞这个

因为这门课要看你真实动手的过程（而不是只看结果对不对）。为了防止有人把过程记录
改掉、删掉来伪造"我很认真"，老师就用哈希链来保证日志没被篡改。所以 README
里才提醒：别删 ~/.labtracker
里的东西——删了你自己的证据链就断了，反而对你不利。

一句话：哈希链就是给日志上的一道"防篡改锁"，让你做过的事经得起核对、别人赖不掉
、自己也删不掉。

这个词在你这里出现，其实是同一个词、两种用法，但核心意思都一样："镜像" =

用法一：events.mirror.jsonl（日志镜像 = 备份副本）

这是你最近看到的那处。它就是把主日志 events.jsonl
原样再存了一份，两个文件内容应该完全一样（就是"镜子里的倒影"）。

为什么要多存一份？ 防意外 + 防篡改：

- 主日志要是被删、被改，镜像还在，就能对照出来
- 所以校验脚本会拿"镜像"和"主日志"比行数：对不上 →
报"镜像与主日志行数不一致，疑似删除记录"（这就是你之前看到那句话的来历）

一句话：镜像日志 = 主日志的"备份双胞胎"，用来抓"谁动了日志"。

用法二：fs.img / 内核镜像（镜像文件 = 磁盘快照）

这是你更早会遇到的另一个意思。这里的"镜像"指的是：把一整块硬盘（或文件系统）的
内容，原样打包成一个文件。

- fs.img（256MB 那个）= xv6 要用的那个 FAT32
磁盘的"镜像文件"，等于把一整块假硬盘"克隆"成一个文件
- 为什么 qemu 需要它？—— qemu 是模拟出来的假电脑，它没有真硬盘，就用 fs.img
这个文件来假装是一块硬盘

类比：就像你给一块硬盘拍了一张"X
光快照"，存成一个文件，需要时照着它还原出一模一样的硬盘。

一句话总结

    你看到的地方           "镜像"指什么               作用
 events.mirror.jsonl  日志的备份副本           抓"日志被删/被改"
 fs.img、内核镜像     磁盘/文件系统的快照文件  给 qemu 当假硬盘用

共同点都是：原样复制出来的"影分身"。

- 它不是"升级后一直待在上面"，而是"临时借用更高级别的能力，干完一件事就回到原

⑤ SBI ✅ 对，补一句：SBI 就是 M 态给 S
态提供的一份"菜单"（关机、定时器、控制台输出这些底层服务都写在菜单上），S
态想用就照着 SBI 的规矩"点"。

重点补：a7 寄存器到底是什么

你卡住不是卡在"a7
放系统调用号"这句话，而是卡在**"寄存器"这三个字本身**。先把这个地基补上：

寄存器 = CPU 身体里自带的、数量极少的"超快小格子"。 每个格子能存一个数。RISC-V
的 CPU 上只有 32 个这种格子（有名字：a0~`a7、t0~t6、pc、sp`……）。

跟内存比：

           内存           寄存器
 容量  巨大（几 G）  极小（就 32 个）
 速度  慢            极快
 比喻  仓库          你手边的草稿纸

那 a0~a7 是干嘛的？——这是一套"约定"（就像打电话要先自报家门）。约定内容是：

▎ 用户程序想请求内核服务时：把"要哪个服务"的编号放进 a7，把"参数"放进
▎ a0~a6，然后 ecall。内核干完活，把结果放进 a0 递回来。

用"点餐"打比方，整条链路就是：

a7   = 你点的菜单编号（几号菜）
a0~a6 = 你的具体要求（少辣、加葱……）
ecall = 按呼叫铃，叫来前台（内核）
前台看了 a7，知道你要几号菜，去后厨做
做完把菜（结果）放进 a0，端回给你

所以你敲 halt 时，底层实际发生的是：用户程序把 halt 的系统调用号塞进 a7，然后
ecall 按铃，内核的 syscall() 函数一看 a7="哦，第 N 号服务"，就派 sys_halt
去执行关机。

---
一句话收束：a7 是"编号槽"，a0~a6 是"参数槽"，ecall 是"按铃"，a0
是"取结果的地方"——全是一套约定好的配合。
