## 卡点记录
> 学生在哪个 CP 卡在哪层、给了什么提示才通
- CP①：器层+技层。错答 13（未查 sysnum.h 现有编号）→ L1 反问"13 有人用吗"自行纠正。
  改文件时误删正确行、留下占位 0 → 埋点核对发现 → 放回 27。追问"0 能不能用" →
  L2 指 syscall() 函数 → 自己读出 `num > 0` 挡掉 0。
- CP②：技层。数指令数成 4（把 `.global halt` 和标签算进去了）→ 引导看 `cat.asm` 的
  objdump 地址行规律 → 自己数出 3，**并主动把这条判据用到 `halt.asm` 上验证了 27 落地**。
- CP③：技层。位置一次放对，但右边写成 `SYS_halt`（号）而非 `sys_halt`（函数），
  且一度以为"缺个逗号" → 给 `grep -rn "sys_halt" kernel/` 让他自己查定义/声明位置才分清。
- CP④：器层+C 语法层。先写成 `exit(sbi_shutdown);`（把要调的函数塞进了参数位）→
  用"拆解 exit(n) 的函数名/参数"反问纠正；又问"关机要什么参数" → 引导去看定义里的
  `(void)`。**两次都不是知识缺口，是 C 语法位置感缺口。** 最终通过，halt 真关机。

## 给下个 lab AI 的提示
> 这个学生的强弱项、该怎么教、要避免什么
- 强项（可加速的地方）：**求知欲强、会主动追问底层概念**（连问 lab 结构 → 构建链路 → ISA →
  文件后缀），会自己上网查，诚实不装懂。**要证据、不轻信结论**——给他一条能自己验证的路
  （哪个文件、哪一行、看什么现象），比给他答案有效得多。
- 弱项（要重点补的地方）：
  ① **C 语法位置感**——不是不懂概念，而是不知道"东西该放哪个位置"（函数名 vs 参数位、
     定义 vs 调用、`->` 链）。补的时候一律用"拆解一个现成例子"的方式，别讲抽象语法。
  ② **工具技能**——不会在文件里搜索、终端复制粘贴不会、VS Code 不会保存（曾因此"以为改了
     其实没保存"）。这些会平白卡住他，**要随手教，别假设他会**。
  ③ **改完文件不核对真实状态**——已发生过"以为改了没保存"和"改错行/删错行"。
     **务必每次核对磁盘真实内容，不要采信口头汇报。**
- 教学建议：讲概念一律落到具体 `文件:行号` / 真实产物上（`cat.asm`、`halt.asm`、`kernel.sym`、
  `qemu.ld` 这套实证非常有效）。C 按需补、一次一个点，**用现成代码当模板拆给他看**，
  别开系统课。不抛术/法/道题。
- ⚠️ 已知环境隐患：本仓库 Makefile **没有 include 任何 .d 文件**（已 grep 确认），改头文件
  （如 sysnum.h）不触发相关 .o 重编。实测：改 sysnum.h 后 `make build` 未重编 target/kernel。
  本 lab 靠"同时改了 .c"侥幸带上，**下个 lab 若只改头文件，注意提醒 clean 重建**。
- 本 lab 收尾时学生主动问"会不会丢失对话/分数"，对进度和记录敏感，**多给确定性反馈**。
