# 学生操作系统实验过程清洗工具

本目录包含三个连续阶段：终端录像与时间线清洗、xv6 源码差异报告、AI/人工贡献识别。它们读取仓库根的 `操作系统实验数据记录/`，并只向 `操作系统实验数据记录-已清洗/` 写入派生材料。终端清洗的模式、缓存和证据约定见[实验过程清洗工具说明](实验过程清洗工具/README.md)。

| 工具 | 用途 | 输出 |
| --- | --- | --- |
| [实验过程清洗工具](实验过程清洗工具/README.md) | 重放 `term` 录像，提取命令、终端对话与时间线 | 每名学生的过程报告与时间线 |
| [代码差异报告工具](代码差异报告工具/README.md) | 对照本地 xv6 无答案基准比较 lab0-lab8 | 每名学生和全班的差异报告 |
| [AI人工贡献识别工具](AI人工贡献识别工具/README.md) | 以过程材料和差异报告生成贡献证据 | assessment JSON 与教师报告 |

先运行实验过程清洗，再运行代码差异报告，最后按需运行贡献识别。抓取工具必须先为每名学生发布唯一的最新提交目录；终端清洗工具随后刷新 `.replay_term_qa.json` 归属，代码差异工具再读取该归属并发布双视图报告。所有入口都支持 `--help`、选择单个学生或显式传入数据根目录。原始数据和无答案基准不会被工具修改，也不会执行学生提交的代码、Makefile 或脚本。

代码差异工具的缓存位于 `操作系统实验数据记录-已清洗/.lab-diff-cache/`，按“学号 × 当前归档 SHA-256 × Lab × 比较规则”复用结构化差异；未变化单元不会再次调用 Git。`--force` 只重建本次选择的学生和 Lab，`--dry-run` 只扫描、显示命中与计划清理项，不写缓存或报告。只有完整扫描和清洗归属都通过时才清理失效缓存，局部学生扫描、归属诊断和输入校验失败不会清理其他学生条目；缓存清理不会删除原始数据、人工文件或正式报告。差异工具的输出路径、状态和失败语义见[代码差异报告工具说明](代码差异报告工具/README.md)。

终端清洗默认使用 `--replay-mode hybrid` 和 `min(12, 可用 CPU 核数)` 个 Python 多进程 worker；需要逐帧回归时使用 `--replay-mode exact`，或在 hybrid 批次中重复传入 `--exact-recording <录像ID>`。录像级缓存长期放在输出根 `.replay-cache/`，只保留当前分析器版本，并在源扫描时清理过期或已移除来源的条目。缓存不会覆盖原始数据、用户文件或正式报告。

证据等级固定为 E1（终端屏幕/录像字节证据）和 E2（明确标注的“采集日志佐证”）。日志佐证附行号、关联置信度和时间语义，不能替代屏幕证据；损坏或缺失 timing 时不生成相对或绝对时间。依赖仅为 Python、`pyte`（LGPL-3.0-or-later）和 `wcwidth`，不要求 `python-isal` 或 `indexed_gzip`。
