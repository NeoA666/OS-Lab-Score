# xv6 源码差异报告工具

代码差异报告工具将每名学生**当前提交**中的 `labs/lab0` 至 `labs/lab8` 与本地无答案基准逐文件比较，生成可供评分和人工复核的 Markdown 报告。工具只读取学生源码和基准，不执行学生代码、Makefile 或脚本，也不复制学生完整源码到缓存。

## 前置条件

- Python 3.9 或更高版本。
- `git` 可从 `PATH` 调用；差异由 `git diff --no-index` 产生。
- 抓取工具已经完成同步，并为每名学生发布唯一的当前提交目录及 `.xv6-sync-source.json`。
- 终端清洗工具已经完成当前提交归属，清洗目录中的 `.replay_term_qa.json` 必须精确指向该提交。

默认路径相对于本脚本所在的仓库位置解析，不依赖启动命令时的当前工作目录：

```text
../../xv6-ai-labs-km-无答案/
../../操作系统实验数据记录/
../../操作系统实验数据记录-已清洗/
```

可用 `--reference-root`、`--submissions-root` 和 `--cleaned-root` 覆盖这些路径。

## 运行

在本目录或任意工作目录执行：

```bash
python3 generate_lab_diff_reports.py --all-labs
python3 generate_lab_diff_reports.py --lab lab3 --student 2406080102
python3 generate_lab_diff_reports.py --all-labs --dry-run
python3 generate_lab_diff_reports.py --lab lab3 --student 2406080102 --force
```

选择参数如下：

| 参数 | 作用 |
| --- | --- |
| `--lab labN` | 只处理指定的 `lab0` 至 `lab8`，可重复传入。 |
| `--all-labs` | 处理 `lab0` 至 `lab8` 全部实验。 |
| `--student <学号或姓名>` | 只处理匹配的学生，可重复传入。未指定时扫描全部当前提交。 |
| `--strict-whitespace` | 将空格、Tab、空白行和行尾空白差异视为变化；默认忽略这些差异。 |
| `--force` | 忽略本次选中学生和 Lab 的缓存命中，重新执行比较并替换对应缓存。 |
| `--dry-run` | 只扫描、计算指纹并显示命中、失效和计划清理项，不执行未命中比较，也不写任何产物。 |

每次运行前先执行严格输入扫描。目录必须有有效的 `.xv6-sync-source.json`，且目录名、`student_id`、姓名、归档 SHA-256 和提交信息相互一致。重复学号、缺少或损坏 marker、身份不一致、符号链接或 junction 等情况只写结构化诊断，不猜测归属、不删除原始提交，也不进入差异缓存。终端清洗归属还必须是 `dual-view-v2`、缓存格式 2 的已完成记录，且没有重放错误；同一来源对应多个清洗目录时整组进入诊断。差异工具依赖抓取工具先收束为每名学生一个最新目录；它不会修改抓取工具或终端清洗工具的归属文件。

## 增量缓存

缓存根目录为：

```text
操作系统实验数据记录-已清洗/.lab-diff-cache/
```

缓存单位是：

```text
学生学号 × 当前归档 SHA-256 × Lab × 比较规则
```

条目保存当前分析器签名、学生与基准源码清单（相对路径、类型、大小和 SHA-256）、两棵源码树指纹、空白符策略、Git 版本和参数、结构化 `DiffEntry` 结果，以及重建报告所需的统计和渲染哈希。缓存不保存学生完整源码。成功比较和可确定的“Lab 不存在”结果可以缓存；Git 失败、读取失败、路径不安全或输入在扫描期间变化时不会写入不可信缓存。

运行日志保留本次实际动作，汇总对已经发布且可复用的正式结果统一显示稳定的 `CACHED`；这样相同输入重复运行时，正式 Markdown/JSON（包括汇总）不会因为动作名称变化而改字节。失败和未处理状态仍在汇总中保留诊断：

- `CACHED`：分析和正式双视图产物都命中且哈希正确。
- `RENDERED`：结构化差异命中，只重新渲染缺失、损坏或模板变化的报告。
- `RECONCILED`：同一归档内容改用新目录名后复用缓存，并刷新来源审计信息。
- `REBUILT`：缓存未命中、已失效或使用 `--force`，重新执行 `git diff`。
- `SKIPPED`、`PARTIAL_FAILED`、`FAILED`：跳过或失败时保留原因；失败不冒充成功缓存。

源码指纹、比较规则、筛选规则、Git 版本或分析器签名变化会使相应单元失效。修改一个学生的一个 Lab 只重算该单元；修改某个基准 Lab 只使该 Lab 的学生缓存失效。Markdown 文案、报告布局或汇总模板变化只需要 `RENDERED`，可以复用结构化差异。

`--dry-run` 不执行未命中比较，也不写缓存、报告、清单、汇总或日志；它会列出命中、失效和按当前完整扫描推断出的计划清理项。只有不带 `--student` 的完整扫描成功后才清理当前源扫描未引用的旧分析器/旧 schema 缓存；局部学生扫描、dry-run、输入验证失败、清洗归属不完整或不安全路径发现时不做全局清理。清理只处理带本工具所有者标记的普通缓存文件，不跟随链接，不删除原始提交、人工文件或正式报告。

## 正式输出

每个成功的学生/Lab 单元会以相同内容发布到两个视图：

```text
操作系统实验数据记录-已清洗/
├─ 按人分类/<学生>/<labN>/代码差异报告工具/代码差异报告.md
├─ 按Lab分类/<labN>/<学生>/代码差异报告工具/代码差异报告.md
└─ 汇总报告/代码差异报告汇总/代码差异报告汇总-labN.md
```

个人报告目录中的 `.lab_diff_reports.json` 是工具所有权清单，只允许工具替换自己登记的报告。个人视图、Lab 视图和清单先写入同卷临时文件并校验，再原子发布；清单提交失败时恢复旧的双视图和清单，首次发布失败会删除新报告，避免留下未登记文件。现有人工文件、外部清单或链接不会被覆盖。汇总稳定按 `Lab → 学号 → 姓名` 排序。

正式 Markdown/JSON 不写入每次运行都会变化的生成时间，而是记录稳定的学生来源指纹、基准指纹、比较规则和分析器签名。因此输入不变时重复运行不会改变正式文件字节。双视图缺失或哈希不一致时，可以从结构化缓存重新渲染，不必重新执行 `git diff`。

当前提交缺少某个 Lab 时，只删除该 Lab 下由本工具登记的旧差异报告，并把“缺失 Lab”作为带固定指纹的 `SKIPPED` 缓存；重复运行会直接复用这个确定状态。普通文件、链接、权限错误或其他不安全路径不视为“缺失”，会保留旧报告并记为失败诊断。如果原始提交整体消失或无法匹配，保留已有正式报告，在汇总和运行日志中显示诊断。差异工具不会因为输入异常删除原始数据。

## 比较范围

每个 Lab 只扫描 xv6 源码和构建入口：`kernel/`、`xv6-user/`、`linker/` 中的受支持源码后缀，以及根目录 `Makefile`/`GNUmakefile` 等明确纳入的 Makefile。`.git`、`.hg`、`.svn`、文档、构建输出和生成的 `xv6-user/usys.S` 等路径排除。二进制文件保留文件级变化和诊断，不把不可读内容伪装成文本补丁。

## 验证

在代码差异报告工具目录运行：

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile generate_lab_diff_reports.py
git diff --check
python3 generate_lab_diff_reports.py --all-labs --dry-run
```

全量验收应按“抓取工具 → 终端清洗工具 → 代码差异报告工具”的顺序进行；首次运行确认双视图和清单完整，随后在相同输入上再次运行，确认所有未变化单元命中缓存且正式 Markdown/JSON 的 SHA-256 不变。

详细的旧流程、缓存键和失效规则见 [REFACTORING.md](REFACTORING.md)。
