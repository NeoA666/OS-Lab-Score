## 基础知识

操作系统实验中编写的代码并不直接运行在你的电脑上。它先经过交叉编译生成 RISC-V 平台的可执行文件，再由 QEMU 模拟的 RISC-V 机器加载启动。这一节先介绍贯穿全课程的基本概念。

### Linux 命令行与包管理器

实验全程在 Linux 命令行下进行。对 Linux 还不熟悉的同学，建议先掌握下面这些常用命令：

- 目录与文件：`cd`、`ls`、`pwd`、`mkdir`、`rm`、`cp`、`mv`
- 权限与进程：`chmod`、`chown`、`ps`
- 重定向与管道：`>`、`<`、`|`
- 包管理（Ubuntu/Debian）：`apt update`、`apt install`、`apt search`
- 系统管理：`sudo`、`man`

每个命令都有大量参数，遇到不认识的命令可以通过 `man <命令>` 查阅手册。

### 交叉编译

日常使用的 PC 通常是 x86_64 架构。本实验的代码却要运行在 RISC-V 上，因此编译过程分为两个角色：

- 宿主机（x86_64）：运行编辑器、make、qemu
- 目标机（RISC-V）：运行 xv6-k210 内核和用户程序

宿主机上普通的 `gcc` 把 C 代码编译成 x86_64 可执行文件。本实验需要的是 `riscv64-unknown-elf-gcc`，这是一个交叉编译器：它在 x86_64 上运行，生成的代码却只能在 RISC-V 上执行。

```text
宿主机(x86_64) → 交叉编译器 → 目标架构(RISC-V)
```

因此整个实验链路里有两套工具：


| 用途           | 工具                                             |
| ------------ | ---------------------------------------------- |
| 编译内核和用户程序    | `riscv64-unknown-elf-gcc` / `-ld` / `-objdump` |
| 模拟 RISC-V 机器 | `qemu-system-riscv64`                          |




### RISC-V 与特权级

RISC-V 是一种开源指令集架构（ISA）。xv6-k210 运行在 RISC-V 64 位（rv64）上。RISC-V 定义了多个特权级，本章涉及三个：

- M-mode（Machine）：最高特权，硬件初始化阶段运行于此，SBI 服务也运行于此
- S-mode（Supervisor）：内核运行的特权级
- U-mode（User）：用户程序运行的特权级

QEMU 启动时先运行 M-mode 的 OpenSBI 固件，由它完成硬件初始化，再跳转到 S-mode 启动 xv6-k210 内核。

### SBI（Supervisor Binary Interface）

SBI 是 RISC-V 上 M-mode 提供给 S-mode 的服务接口。操作系统运行前，SBI 负责完成基本的硬件初始化，并向操作系统提供关机、复位、定时器、控制台输出等底层服务。

QEMU 7.0 及以上版本内置了 OpenSBI 固件。本实验通过 `-bios default` 参数让 QEMU 加载自带的 OpenSBI，仓库里 `bootloader/SBI/` 目录下的文件无需改动。

### QEMU 系统模拟

QEMU 是一个开源的系统模拟器。本实验使用 `qemu-system-riscv64` 配合 `-machine virt` 参数，模拟一台名为 `virt` 的 RISC-V 虚拟机，包含：

- 一个或多个 rv64 CPU（`-smp N`）
- 一段连续物理内存（`-m 128M`）
- 一个 virtio 块设备，挂载 `fs.img` 作为磁盘
- 串口控制台（`-nographic` 参数把内核输出直接打到当前终端）

运行时按 `Ctrl+A` 松开后再按 `X` 可退出 QEMU。

### FAT32 文件系统

xv6-k210 使用 FAT32 作为根文件系统。所有用户程序（`init`、`sh`、`ls`、`cat` 等）先经过交叉编译，再被打包进一个名为 `fs.img` 的 FAT32 镜像，内核启动后从这个镜像里加载用户程序。

`fs.img` 的生成依赖宿主机上的 `mkfs.vfat` 工具，并通过 `mount` 写入文件，因此需要管理员权限。

### Makefile 入门

`make` 是一个自动化构建工具，它读入 `Makefile`，按其中定义的"规则"编译和链接目标文件。一个 Makefile 规则形如：

```makefile
目标: 依赖
	命令
```

命令行前必须是一个 Tab 字符，不能用空格代替。

xv6-k210 的 `Makefile` 提供了三个主要 target：


| target       | 作用                       |
| ------------ | ------------------------ |
| `make build` | 交叉编译内核和用户程序              |
| `make fs`    | 生成 FAT32 文件系统镜像 `fs.img` |
| `make run`   | 编译并启动 QEMU 运行 xv6-k210   |


各 lab 的 `Makefile` 已默认设置 `platform := qemu`，因此课程中的常规命令无需再带平台参数。xv6-k210 同时支持 K210 真实硬件和 QEMU 模拟两个平台，本课程只使用 QEMU；只有显式切换到 K210 真机时才需要指定 `platform=k210`。

## 代码导读

本节从项目结构、内核代码组织和启动调用链三个层面，介绍 xv6-k210 的整体面貌。lab0 不要求读懂源码细节，重点在于建立"代码是怎么组织的"和"上电后怎么一节一节跑起来的"这两层认识。

### 项目结构

lab0 目录下的顶层文件和文件夹：


| 条目                    | 类型     | 作用                                         |
| --------------------- | ------ | ------------------------------------------ |
| `Makefile`            | 构建入口   | 定义 `build`/`fs`/`run` 三个 target，是整个实验的入口   |
| `kernel/`             | 内核源码   | 本课程要读懂和修改的核心代码                             |
| `xv6-user/`           | 用户程序   | shell、ls、cat 等用户态程序，编译后打包进 `fs.img`        |
| `linker/`             | 链接脚本   | 告诉链接器内核各段应放到内存的什么地址                        |
| `bootloader/`         | SBI 固件 | QEMU 模式下不直接使用，由 `-bios default` 加载 OpenSBI |
| `doc/`                | 文档资料   | 原始说明                                       |
| `README`、`README.md`  | 简要入口   | 实验概览                                       |
| `实验指导.md`、`CLAUDE.md` | 教学文档   | 实验指导和 AI 行为约束                              |


每个文件夹对应的阶段：

- **上电阶段** → `bootloader/`（QEMU 用 OpenSBI）
- **启动阶段** → `linker/`（指定内核加载地址）、`kernel/entry_qemu.S`（内核第一条指令）
- **运行阶段** → `kernel/`（内核主体）、`xv6-user/`（用户程序）



### 内核代码组织

`kernel/` 目录下的源文件按功能可分为若干组：


| 分组      | 文件                                                                         | 职责                       |
| ------- | -------------------------------------------------------------------------- | ------------------------ |
| 启动      | `entry_qemu.S`、`main.c`                                                    | 上电后第一条内核指令、内核主循环         |
| 内存      | `kalloc.c`、`vm.c`                                                          | 物理页分配、页表管理               |
| 进程      | `proc.c`、`swtch.S`                                                         | 进程控制块、上下文切换              |
| 陷阱与系统调用 | `trap.c`、`syscall.c`、`sysproc.c`、`trampoline.S`、`kernelvec.S`              | 用户态陷入内核、syscall 分发与实现    |
| 文件系统    | `fat32.c`、`file.c`、`bio.c`、`disk.c`、`virtio_disk.c`、`exec.c`、`pipe.c`      | FAT32 文件系统、文件对象、缓冲区、磁盘驱动 |
| 驱动      | `uart.c`、`plic.c`、`console.c`、`timer.c`                                    | 串口、中断控制器、控制台、定时器         |
| 同步      | `spinlock.c`、`sleeplock.c`                                                 | 自旋锁、睡眠锁                  |
| K210 专用 | `entry_k210.S`、`fpioa.c`、`gpiohs.c`、`spi.c`、`sdcard.c`、`dmac.c`、`sysctl.c` | K210 硬件相关，QEMU 模式下不参与    |


各 lab 按主题对应到不同分组：

- lab1 syscall → 陷阱与系统调用组
- lab2 进程 → 进程组
- lab3 内存 → 内存组
- lab5 lazy → 内存组 + 陷阱组
- lab7 文件系统 → 文件系统组



### 启动到 shell 的调用链

QEMU 启动到 shell 提示符出现，经历以下阶段：

```text
[1] QEMU -bios default
     └─ 加载 OpenSBI 固件到 0x80000000（M-mode）

[2] OpenSBI 完成硬件初始化
     └─ 跳转到内核入口 0x80200000（S-mode）

[3] kernel/entry_qemu.S: _entry
     └─ 为每个 hart 设置栈
     └─ call main

[4] kernel/main.c: main()
     ├─ consoleinit()     // 控制台
     ├─ printfinit()      // printf
     ├─ kinit()           // 物理页分配器
     ├─ kvminit()         // 内核页表
     ├─ kvminithart()     // 开启分页
     ├─ trapinithart()    // 安装 trap 向量
     ├─ procinit()        // 进程表
     ├─ plicinit()        // 中断控制器
     ├─ disk_init()       // 磁盘
     ├─ binit()           // 缓冲区
     ├─ fileinit()        // 文件表
     ├─ userinit()        // 创建第一个用户进程 init
     └─ scheduler()       // 开始调度

[5] scheduler() swtch 到 initcode → exec("/init")
     └─ init 进程在 xv6-user/init.c 中

[6] xv6-user/init.c: main()
     ├─ fork 出 sh 子进程
     └─ sh 在 xv6-user/sh.c 中读取用户输入

[7] shell 提示符 -> / $ 出现，等待命令
```

`lab0` 的范围到此为止。shell 提示符出现即表示上述调用链完整跑通。

### 各阶段对应的实际文件


| 阶段    | 文件                                      | 关键函数              |
| ----- | --------------------------------------- | ----------------- |
| 上电加载  | （QEMU 内置）OpenSBI                        | —                 |
| 内核入口  | `kernel/entry_qemu.S`                   | `_entry`          |
| 内核主流程 | `kernel/main.c`                         | `main`            |
| 用户态入口 | `xv6-user/initcode.S`、`xv6-user/init.c` | `initcode`、`main` |
| shell | `xv6-user/sh.c`                         | `main`、`getcmd`   |


这些函数的内部细节在 lab1 之后会逐步展开。构建后生成的 `target/kernel.asm` 中可以查到每个函数的汇编形式，便于在反汇编中定位启动过程。

### 任务2：安装 GNU 交叉编译工具链



#### 步骤1：确认工具链是否已安装

```bash
riscv64-unknown-elf-gcc --version
# 或者
riscv64-linux-gnu-gcc --version
```

如果你看到版本号输出（例如 `10.1.0`），说明已经装好。如果提示 `command not found`，进入步骤2。

#### 步骤2：安装工具链

RISC-V 工具链有几种来源：

- Ubuntu 自带的 `gcc-riscv64-unknown-elf` 或 `gcc-riscv64-linux-gnu` 包
- SiFive 官方预编译工具链
- 自行从 riscv-gnu-toolchain 项目源码编译

三种方式都可以，工具链的可执行文件前缀必须与 `Makefile` 中的 `TOOLPREFIX` 一致。

Ubuntu 包管理器安装示例：

```bash
sudo apt install gcc-riscv64-unknown-elf
# 或
sudo apt install gcc-riscv64-linux-gnu
```



#### 步骤3：确认 TOOLPREFIX

打开仓库里的 `Makefile`，找到这一行：

```makefile
TOOLPREFIX	:= riscv64-unknown-elf-
# TOOLPREFIX	:= riscv64-linux-gnu-
```

`TOOLPREFIX` 是工具链命令的公共前缀，Makefile 会用它拼出 `$(TOOLPREFIX)gcc`、`$(TOOLPREFIX)ld` 等命令。

- 装的是 `riscv64-unknown-elf-gcc`，前缀就是 `riscv64-unknown-elf-`，保持默认即可
- 装的是 `riscv64-linux-gnu-gcc`，需要把前缀改为 `riscv64-linux-gnu-`，并注释掉原来的行

TOOLPREFIX 与实际工具链不匹配会导致编译失败。

#### 步骤4：验证工具链

跑一次版本确认：

```bash
riscv64-unknown-elf-gcc --version
riscv64-unknown-elf-ld --version
```

两条命令都能输出版本号即可。

#### Ubuntu 24.04 / GCC 13 兼容说明

Ubuntu 24.04 当前安装的 `riscv64-unknown-elf-gcc` 通常为 GCC 13。GCC 13 会把 `xv6-user/sh.c` 中用于遍历命令树的递归函数 `runcmd()` 诊断为 `-Winfinite-recursion`。这是新版编译器对旧版 xv6 代码的兼容性诊断，不表示 shell 一定会发生无限递归。

如果 Makefile 同时启用了 `-Werror`，该警告会被提升为错误，典型输出为：

```text
error: infinite recursion detected [-Werror=infinite-recursion]
cc1: all warnings being treated as errors
```

本实验仓库的 `lab0` 到 `lab8` 已在 `CFLAGS` 中加入：

```makefile
-Wno-error=infinite-recursion
```

它只允许这一项保留为警告，其他警告仍受 `-Werror` 检查。使用旧版实验副本时，可对照当前 Makefile 补上该选项，不建议直接删除整个 `-Werror`。

链接阶段出现下面的输出也只是警告，不是构建失败：

```text
warning: ... has a LOAD segment with RWX permissions
```

判断构建是否成功，应看最后是否出现 `make: *** ... Error`，以及 `target/kernel` 是否生成。

### 任务3：安装 QEMU 系统模拟器



#### 步骤1：确认 QEMU 是否已安装

```bash
qemu-system-riscv64 --version
```

期望版本 ≥ 7.0。如果未装或版本太低，进入步骤2。

#### 步骤2：用包管理器安装（推荐）

Ubuntu 24.04 自带的 QEMU 版本通常够用：

```bash
sudo apt install qemu-system-misc
```

安装后再跑一次 `qemu-system-riscv64 --version` 确认。

#### 步骤3：（可选）从源码编译更高版本

发行版自带的 QEMU 版本不够（< 7.0）时，可以从源码编译。这一步比较耗时，一般不需要。

依赖包：

```bash
sudo apt install autoconf automake autotools-dev curl libmpc-dev libmpfr-dev libgmp-dev \
              gawk build-essential bison flex texinfo gperf libtool patchutils bc ninja-build \
              zlib1g-dev libexpat-dev pkg-config libglib2.0-dev libpixman-1-dev git tmux python3
```

下载、编译、安装：

```bash
cd /usr/local
sudo wget https://download.qemu.org/qemu-7.0.0.tar.xz
sudo tar xJf qemu-7.0.0.tar.xz
cd qemu-7.0.0
./configure --target-list=riscv64-soft-mmu,riscv64-linux-user
make -j$(nproc)
sudo make install
```

`riscv64-softmmu` 是系统模拟模式（生成 `qemu-system-riscv64`），`riscv64-linux-user` 是用户态模拟模式（生成 `qemu-riscv64`）。本课程只用前者。

#### 步骤4：验证 QEMU

```bash
qemu-system-riscv64 --version
```

期望输出形如：

```text
QEMU emulator version 7.0.0
Copyright (c) 2003-2022 Fabrice Bellard and the QEMU Project developers
```



### 任务4：构建 xv6-k210 内核



#### 步骤1：进入 lab0 目录

```bash
cd /path/to/xv6-ai-labs/lab0
```



#### 步骤2：清理旧产物（首次构建可跳过）

```bash
make clean
```



#### 步骤3：构建内核

```bash
make build
```

`build` 这个 target 实际做了两件事：

1. 用交叉编译器把 `kernel/*.c`、`kernel/*.S` 编译、链接成 ELF 内核镜像 `target/kernel`
2. 编译 `xv6-user/` 下的所有用户程序（`init`、`sh`、`ls`、`cat` 等）

构建成功后，当前目录会出现 `target/` 文件夹，其中包含 `kernel` 镜像，以及用于调试的 `kernel.asm`（反汇编）和 `kernel.sym`（符号表）。

构建失败常见原因：`TOOLPREFIX` 与工具链不匹配，或 QEMU 版本过低。

### 任务5：生成文件系统镜像 fs.img

xv6-k210 启动后需要从 `fs.img` 加载用户程序。这一步把 `xv6-user/` 下编译出的所有用户程序打包进一个 FAT32 镜像。

#### 步骤1：确认 mkfs.vfat 可用

```bash
mkfs.vfat --help
```

如果没有，安装：

```bash
sudo apt install dosfstools
```



#### 步骤2：生成 fs.img

```bash
make fs
```

这一步内部做的事情（对应 `Makefile` 里的 `fs:` target）：

1. 如果 `fs.img` 不存在，用 `dd` 创建一个 256 MB 的空文件，再用 `mkfs.vfat -F 32` 格式化为 FAT32
2. 用 `sudo mount` 把它挂到 `/mnt`
3. 把 `xv6-user/_*` 拷进去（去掉前缀 `_`），同时建一个 `bin/` 子目录放一份副本
4. `umount` 卸载

`mount` 操作需要管理员权限，第一次运行会要求输入 sudo 密码。

#### 步骤3：（可选）免 sudo 方案

如果不想每次都输密码，可以改用 `mtools`（无需 mount）。安装：

```bash
sudo apt install mtools
```

`mtools` 提供 `mmd`、`mcopy` 等命令，可以直接读写 FAT 镜像。具体改 Makefile 的方法本 lab 不展开。默认推荐使用 `sudo make fs`。

#### 步骤4：确认产物

```bash
ls -lh fs.img
```

期望看到一个 256 MB 左右的文件。

### 任务6：启动 xv6-k210



#### 步骤1：执行 run target

```bash
make run
```

`run` target 等价于：

```bash
make build
qemu-system-riscv64 \
    -machine virt \
    -kernel target/kernel \
    -m 128M \
    -nographic \
    -smp 2 \
    -bios default \
    -drive file=fs.img,if=none,format=raw,id=x0 \
    -device virtio-blk-device,drive=x0,bus=virtio-mmio-bus.0
```

每个参数的含义如下：


| 参数                       | 含义                            |
| ------------------------ | ----------------------------- |
| `-machine virt`          | 模拟 QEMU 的通用 RISC-V 虚拟机 `virt` |
| `-kernel target/kernel`  | 加载我们的内核 ELF 镜像                |
| `-m 128M`                | 给虚拟机 128 MB 内存                |
| `-nographic`             | 不开图形窗口，串口直接打到当前终端             |
| `-smp 2`                 | 2 个 CPU 核心                    |
| `-bios default`          | 用 QEMU 自带的 OpenSBI 固件         |
| `-drive ... -device ...` | 把 `fs.img` 作为 virtio 块设备挂上    |




#### 步骤2：观察启动输出

正常启动会按顺序出现以下内容：

1. OpenSBI banner：一段 ASCII 艺术的 `OpenSBI v1.0`，以及平台信息（HART 数、内存布局、SBI 版本等）
2. xv6-k210 banner：内核自己的输出
3. `hart 0 init done`
4. `init: starting sh`
5. `-> / $`（shell 提示符）

看到 `-> / $` 表示内核和文件系统已经启动，shell 已就绪。还应输入 `ls` 并按回车，确认控制台输入链路正常。

#### QEMU 8.2 / OpenSBI 1.3 控制台输入兼容说明

Ubuntu 24.04 的 QEMU 8.2 通常内置 OpenSBI 1.3。旧版 xv6-k210 的 QEMU 输入代码依赖 UART 外部中断触发 `sbi_console_getchar()`；在这一组合下可能出现：

- OpenSBI、内核和 shell 输出均正常；
- 已经看到 `-> / $`；
- 但键盘字符不回显，按回车也没有反应。

这不是 SSH 导致的。`qemu-system-riscv64 -nographic` 可以正常运行在 SSH 终端中，不要求图形桌面。本仓库已在 QEMU 模式下通过时钟中断轮询 OpenSBI 控制台输入，以兼容新版 QEMU/OpenSBI。

如果修改前的 QEMU 进程仍在运行，它加载的还是旧内核。修复或更新源码后，应先按 `Ctrl+A`、松开、再按 `X` 退出，然后重新执行：

```bash
make run
```

`make run` 会重新构建有变化的源文件并加载新内核，不需要重新生成 `fs.img`。

#### 步骤3：退出 QEMU

按 `Ctrl+A`，松开后按 `X`，QEMU 会立即退出。

### 任务7：在 shell 里试几个命令

在 `-> / $` 提示符下试：

```text
-> / $ ls
-> / $ ls /bin
-> / $ cat README
```

期望的输出：

- `ls` 列出根目录下的文件（`init`、`sh`、`README`、`bin` 等）
- `ls /bin` 列出 `bin/` 下的所有用户程序
- `cat README` 打印 README 文件内容

至此 lab0 完成。

### 现象分层定位

后续 lab 出问题时，可按下面三类进行定位：


| 故障层   | 现象                                      | 排查方向                                |
| ----- | --------------------------------------- | ----------------------------------- |
| 编译层   | `make build` 报错                         | 工具链、TOOLPREFIX、源码本身                 |
| 文件系统层 | 内核启动但 `panic: init exiting`、找不到 `init`  | `fs.img` 是否生成、`_init` 是否被拷进去        |
| 运行层   | QEMU 启动后无 banner、卡死、`unexpected scause` | QEMU 版本、`-m` 内存、`-bios default` 是否对 |




### 用 gdb 调试内核（可选，进阶）

后续 lab 需要调试内核时，可以用 gdb 配合 QEMU。

步骤1：在一个终端启动 QEMU 并等待 gdb 接入：

```bash
qemu-system-riscv64 -machine virt -kernel target/kernel -m 128M -nographic \
    -bios default -drive file=fs.img,if=none,format=raw,id=x0 \
    -device virtio-blk-device,drive=x0,bus=virtio-mmio-bus.0 \
    -s -S
```

`-s` 让 QEMU 在 TCP 1234 端口等待 gdb，`-S` 让 QEMU 启动后暂停，等 gdb 接入再开始执行。

步骤2：在另一个终端启动 gdb：

```bash
riscv64-unknown-elf-gdb target/kernel \
    -ex 'set arch riscv:rv64' \
    -ex 'target remote localhost:1234'
```

之后可以在 gdb 里设断点、单步、查看寄存器和内存。本章只要了解这种调试方式即可，lab1 之后会经常使用。

### 反汇编和符号表

构建过程会顺带生成两个调试辅助文件：

- `target/kernel.asm`：内核反汇编，把每条指令和源码行对应起来
- `target/kernel.sym`：内核符号表，列出所有函数和全局变量的地址

排查 panic 时，可把 `sepc`（异常指令地址）拿到 `kernel.sym` 中查找，定位出错的函数。

## 常见问题（FAQ）


| 现象                                                         | 原因 / 解决                                                                                |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `make build` 报 `riscv64-...-gcc: command not found`        | 工具链没装或 `TOOLPREFIX` 没对，回任务2                                                            |
| `make build` 报 `error: unrecognized command-line option` 等 | 工具链版本和内核期望不匹配，换 SiFive 预编译工具链                                                          |
| GCC 13 报 `infinite recursion detected` 并因 `-Werror` 停止     | 新编译器对 `sh.c:runcmd()` 的兼容性诊断；确认 Makefile 的 `CFLAGS` 含 `-Wno-error=infinite-recursion`  |
| 链接器提示 `LOAD segment with RWX permissions`                  | 警告而非错误；若最终生成 `target/kernel` 可继续实验                                                     |
| `qemu-system-riscv64: ROM regions are overlapping`         | QEMU 版本太旧或 `-m` 内存太小。确认 `qemu-system-riscv64 --version` ≥ 7.0，且 `Makefile` 里 `-m 128M` |
| `qemu-system-riscv64: command not found`                   | QEMU 没装，回任务3                                                                           |
| `panic: init exiting` 或 `[exec] /init not found`           | `fs.img` 没生成或损坏。删掉 `fs.img` 重新 `make fs`                                               |
| 启动后看不到 `-> / $`                                            | 首次启动较慢，等 10~20 秒；或检查 `fs.img` 是否包含 `init`/`sh`                                         |
| 看到 `-> / $`，但输入不回显、回车无反应                                   | QEMU 8.2/OpenSBI 1.3 与旧控制台输入实现不兼容；使用当前仓库的兼容修复，退出旧 QEMU 后重新 `make run`。SSH 无需改用桌面端      |
| `make fs` 报 `mount: operation not permitted`               | 没用 sudo，或 `/mnt` 已被占用。先 `sudo umount /mnt` 再重试                                         |
| 退出 QEMU 后终端显示异常                                            | 输入 `reset` 回车重置终端                                                                      |

## 思考题（可选，不影响验收）

下列题目用于加深理解，lab1 开始会反复接触。

1. **为什么内核要 SBI？** 提示：内核刚启动时处于什么特权级？谁有权限配置中断/定时器？
2. **QEMU** `-machine virt` **模拟的是什么硬件？** 提示：查阅 QEMU 文档中 `virt` 的内存布局和外设。
3. **为什么用 FAT32 而不是 xv6 原版的日志文件系统？** 提示：xv6-k210 为 K210 硬件移植，K210 通常从 SD 卡启动，而 SD 卡传统上是 FAT32。
4. **为什么** `Makefile` **要写死** `TOOLPREFIX`**？** 提示：不同发行版、不同来源的工具链命名前缀不一样。
5. `-bios default` **加载了什么？** 提示：OpenSBI。它运行在什么特权级？与内核之间的接口是什么？
