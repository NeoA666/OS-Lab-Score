## 基础知识

### 立即分配 vs 懒分配

xv6 原版 `sbrk(n)` 是立即分配：

```text
用户调 sbrk(4096)
  → sys_sbrk → growproc(4096)
  → uvmalloc: 立即 kalloc 一页 + mappages 建页表映射 + 清零
  → sz 抬高 4096
  → 返回旧 sz
```

懒分配只承诺不兑现：

```text
用户调 sbrk(4096)
  → sys_sbrk: 只抬高 sz，不调 growproc
  → 返回旧 sz

用户首次访问新区域
  → 该地址暂无页表映射，触发 page fault
  → 内核 usertrap 检测到 fault 地址在 [0, sz) 内
  → 视为合法 lazy 地址：kalloc 一页 + mappages
  → 返回用户态重试访问 → 成功
```

懒分配节省了什么：

- 程序申请大块内存但实际只用一小部分时，物理页只在被访问时才分配
- `sbrk(1MB)` 但只读写前 100 字节，懒分配只占 1 页，立即分配占 256 页
- 启动开销也变小：fork/exec 时拷贝的页表项更少

### RISC-V page fault

访问一个虚拟地址，如果页表里没有合法映射（或权限不匹配），CPU 触发异常。RISC-V 把这种异常归入 trap，由 `stvec` 指向的处理入口接管（xv6 用户态陷阱入口是 `usertrap`）。

相关寄存器：

- `scause`：异常原因编码。本 lab 关注三类 page fault
- `stval`：触发异常的虚拟地址

三种 page fault 的 scause 编码：

| scause | 含义 | 触发指令 |
|--------|------|----------|
| 13 | Load Page Fault | `ld` / `lw` 等读操作访问非法地址 |
| 15 | Store/AMO Page Fault | `sd` / `sw` 等写操作访问非法地址 |
| 12 | Instruction Page Fault | 取指时遇到非法地址（如代码段未映射） |

本 lab 的 lazy 场景主要遇到 13 和 15（读写新申请内存），12 出现在 demand paging（代码段延迟加载）场景，本 lab 主线不处理但思路一致。

### xv6 用户态陷阱入口 `usertrap`

`usertrap` 是用户态发生 trap（syscall / 中断 / 异常）时的入口。它的判断流程：

```text
读 scause
  │
  ├─ scause == 8（ecall）        → 系统调用：syscall()
  ├─ devintr() != 0              → 设备中断：处理时钟等
  └─ 其他                          → 意外异常：默认 kill 进程
```

第三条分支（"其他"）原本是兜底逻辑：所有未识别的异常一律 kill 进程。lazy 分配需要在这条分支里加判断——如果 scause 是 page fault 且 fault 地址在 `[0, sz)` 内，认为是合法的 lazy 地址，分配物理页；否则才 kill。

### lazy 补映射需要做什么

合法的 lazy page fault 进入分支后，需要：

1. 从 `stval` 取 fault 地址
2. 页对齐：`va = PGROUNDDOWN(fault_addr)`
3. `kalloc()` 一页物理内存
4. `memset(mem, 0, PGSIZE)` 清零
5. `mappages(p->pagetable, va, PGSIZE, (uint64)mem, PTE_R | PTE_W | PTE_X | PTE_U)` 建立映射
6. 用户态重试访问 → 成功

注意权限标志：必须包含 `PTE_U`，否则用户态访问仍会触发 fault。`PTE_R|PTE_W|PTE_X` 表示可读写执行，本 lab 简化处理，全开即可。

分配失败处理：`kalloc` 返回 NULL 时（物理内存不足），不能继续，把 `p->killed` 置 1，让进程在下次 `exit` 检查时退出。

### CP① CP② 必须配套

只改 CP① 不改 CP②：

```text
sbrk 不分配 → sz 抬高 → 访问新页 → page fault → usertrap 第三分支 → kill
```

进程一访问新内存就被杀。

只改 CP② 不改 CP①：

- 原 `sbrk` 已经立即分配，新页都已经映射好
- CP② 的 lazy 分支永远不会触发（因为没有 page fault）
- 改动只是死代码

两个 CP 必须配套实现，缺一个就崩。

### `sys_sbrk` 当前实现（`kernel/sysproc.c` 约 116 行）

```c
uint64
sys_sbrk(void)
{
  int addr;
  int n;

  if(argint(0, &n) < 0)
    return -1;
  addr = myproc()->sz;
  if(growproc(n) < 0)   // CP①：学生改成 lazy 策略，推迟物理页分配
    return -1;
  return addr;
}
```

这是原版的立即分配实现：`growproc(n)` 内部调 `uvmalloc`，立即分配物理页并建立页表映射。

CP① 的改造点：把 `growproc(n)` 这一步替换成只更新 `sz`。`argint(0, &n)` 和 `addr = myproc()->sz` 以及 `return addr` 都保留。

### `usertrap` 当前实现（`kernel/trap.c` 约 51 行）

```c
void
usertrap(void)
{
  int which_dev = 0;

  if((r_sstatus() & SSTATUS_SPP) != 0)
    panic("usertrap: not from user mode");

  w_stvec((uint64)kernelvec);

  struct proc *p = myproc();
  p->trapframe->epc = r_sepc();

  if(r_scause() == 8){
    // 系统调用
    if(p->killed)
      exit(-1);
    p->trapframe->epc += 4;
    intr_on();
    syscall();
  }
  else if((which_dev = devintr()) != 0){
    // 设备中断
  }
  else {
    // 【AI-CHECKPOINT ②】在此处 kill 逻辑之前加 lazy 分支
    printf("\nusertrap(): unexpected scause %p pid=%d %s\n", r_scause(), p->pid, p->name);
    printf("            sepc=%p stval=%p\n", r_sepc(), r_stval());
    p->killed = 1;
  }

  if(p->killed)
    exit(-1);

  if(which_dev == 2)
    yield();

  usertrapret();
}
```

CP② 的改造点：在第三分支（`else`）的 `printf` / `p->killed = 1` 之前，加 lazy 判断。

### 关键底层接口

#### `r_scause` / `r_stval`（`kernel/include/riscv.h`）

读 CSR 寄存器的内联函数。`r_scause()` 返回 trap 原因编码；`r_stval()` 返回异常辅助信息（page fault 时是 fault 地址）。

#### `PGROUNDDOWN(va)` / `PGROUNDUP(va)`

把虚拟地址按页大小（4096 字节）对齐。`PGROUNDDOWN(va)` 返回包含 `va` 的那一页的起始地址。

#### `kalloc()` / `kfree()`（`kernel/kalloc.c`）

xv6 物理页分配器。`kalloc()` 返回一页 4KB 物理内存（已清零不保证，调用方需自行 `memset`）；`kfree(mem)` 释放一页。

#### `mappages(pagetable, va, size, pa, perm)`（`kernel/vm.c`）

在指定页表里建立 `[va, va+size)` 到 `[pa, pa+size)` 的映射。`perm` 是 PTE 标志位组合。返回 0 成功，-1 失败。

### CP① CP② 在调用链中的位置

```text
用户 sbrk(4096)
  ↓
sys_sbrk（CP①）：抬高 sz，不立即分配
  ↓ 返回旧 sz

用户写 mem[0]（未映射）
  ↓
触发 store page fault（scause=15）
  ↓
usertrap 第三分支
  ↓
【CP②】检查 scause==13||15 && stval < p->sz
  ├─ 是合法 lazy 地址 → kalloc + memset + mappages → 返回用户态重试
  └─ 否则 → 维持原 kill 逻辑
```

### 任务2：CP① 修改 `sys_sbrk` 为懒分配

#### 步骤1：阅读当前 `sys_sbrk`（约 116 行）

源码见"代码导读"小节。注意三个关键步骤：

1. `argint(0, &n)` 取增量参数
2. `addr = myproc()->sz` 记录旧 sz
3. `growproc(n)` 立即分配 + 抬高 sz

#### 步骤2：理解懒分配改造

CP① 要做的是把"立即分配 + 抬高 sz"变成"只抬高 sz"。具体替换：

- 把 `if(growproc(n) < 0) return -1;` 这一行换成只更新 `sz` 的代码
- 不调用 `growproc`，不调用 `uvmalloc`
- `addr = myproc()->sz` 和 `return addr` 都保留（sbrk 语义不变）

注意 `n` 可正可负。本 lab 主线只考虑 `n > 0` 的扩展场景；负 `n`（收缩）的处理可以保留原 `growproc(n)` 调用，避免引入额外复杂度。

#### 步骤3：改完后单独测试

CP① 改完后单跑 `lazytest` 会出现：

```text
sbrk returned 0x<地址>
usertrap(): unexpected scause 0x000000000000000f pid=... sepc=... stval=...
```

这是预期的：sbrk 不分配 → 访问新页触发 store page fault（scause=15）→ usertrap 还没加 lazy 分支 → 走 kill 分支打印 unexpected scause。

这个失败现象证明 CP① 已生效（sz 抬高了但没分配），现在需要 CP② 接住。

### 任务3：CP② 在 `usertrap` 加入 lazy 分支

#### 步骤1：阅读当前 `usertrap` 第三分支（约 84 行）

```c
else {
    // CP② 学生在此加 lazy 判断
    printf("\nusertrap(): unexpected scause %p pid=%d %s\n", r_scause(), p->pid, p->name);
    printf("            sepc=%p stval=%p\n", r_sepc(), r_stval());
    p->killed = 1;
}
```

#### 步骤2：实现 lazy 分支

在 `printf` 之前加判断：

1. 读 `va = r_stval()`
2. 检查 `(r_scause() == 13 || r_scause() == 15) && va < p->sz`（合法 lazy 地址）
3. 页对齐 `va = PGROUNDDOWN(va)`
4. `char *mem = kalloc()`；失败则 `p->killed = 1`
5. 成功：`memset(mem, 0, PGSIZE)`；`mappages(p->pagetable, va, PGSIZE, (uint64)mem, PTE_R | PTE_W | PTE_X | PTE_U)`
6. 不满足 lazy 条件（scause 不是 page fault 或地址越界）：维持原 printf + kill 逻辑

注意权限标志：必须包含 `PTE_U`，否则用户态访问仍会再次触发 fault，循环不止。

## 常见问题（FAQ）

| 现象 | 原因 / 解决 |
|------|------------|
| `lazytest` 输出 `sbrk failed` | CP① 改错，`argint` 或 `return` 路径被破坏 |
| `lazytest` 卡死无输出 | CP② 的 lazy 分支导致死循环（如 `mappages` 失败但没 kill） |
| 看到 `usertrap(): unexpected scause 0xd` 然后 kill | scause=13 是 load page fault，CP② 的条件没覆盖；检查是否同时检查 13 和 15 |
| 看到 `usertrap(): unexpected scause 0xf` 然后 kill | scause=15 是 store page fault，CP② 条件没生效；检查 `va < p->sz` 写法 |
| 反复 page fault 同一地址 | `mappages` 的权限标志缺 `PTE_U`，用户态访问仍触发 fault |
| 系统启动失败 / shell 不出现 | CP② 误把 scause==8（syscall）也分流到 lazy，导致 syscall 失效 |
| 启动早期 panic | CP① 把 `growproc` 误改成 `myproc()->sz = n`（少了 `+=`），破坏了 `sz` 累加语义 |
