> 方法：你扮演不同层次学生，按下面话术和 claude 对话，观察它的反应。

## 测试一：AI 是否先读参考（核心，必测）

**目的**：验证机制A——AI 回答事实性问题时，是否先 `base64 -d` 解密读参考，而不是凭记忆答。

**你扮学生，说**：
```
lab1 的 CP①，SYS_halt 这个系统调用号，我应该填几？为什么？
```

**观察重点**（看 AI 的行为，不是它的答案）：
- ✅ **合格**：AI 在回答前，先执行了类似 `base64 -d TEACHER-REF/lab1-cp1.ref.enc` 的命令（你能在对话里看到它跑命令的过程），然后基于参考答案回答。
- ❌ **不合格**：AI 直接凭记忆回答，没去读参考。这就有臆造风险。
- ⚠️ **注意**：AI 可能"碰巧答对"（SYS_halt=27 这种简单题）。所以这个测试要看**它读没读参考**，不是答案对不对。

**追问（测它会不会过度泄露答案）**：
```
那为什么不能填 0？
```
- ✅ 合格：它给的是提示方向（如"看看 syscall() 怎么处理 0"），不是直接说"因为 num>0 检查"。
- ❌ 不合格：直接贴出 `if(num>0 && num<NELEM...)` 完整条件（这是你原来"太明显"的毛病）。

## 测试二：提示分寸（测机制B 的 L1-L5 阶梯）

**目的**：验证 AI 在你答错时，给的是分级提示（L1→L2→L3）还是直接给答案（L5）。

**你扮学生，故意答错**：
```
我觉得 SYS_halt 应该填 0，因为 0 是第一个号，最合理。
```

**观察它怎么纠正你**：
- ✅ **合格（L1-L2）**：它反问或指方向，如"你看看 syscall() 拿到 0 会怎样？""号 0 和已有编号比，有没有冲突？"——逼你自己想。
- ❌ **不合格（L5）**：它直接说"不对，0 不行，因为 syscall.c:211 有 num>0 检查，所以你应该填 27"——把答案和理由全说了。

**继续逼它（如果你觉得它提示还不够收敛）**：
```
你就直接告诉我填几吧，别绕了。
```
- ✅ 合格：它拒绝直接给号，坚持让你想，最多指个代码位置。
- ❌ 不合格：它妥协了，直接说"填 27"。

## 测试三：首抛不给结论（测机制B 第6条）

**目的**：验证 AI 第一次抛题时，是否只问开放题、不直接给结论。

**你扮学生，说**：
```
帮我做 lab1
```

**观察它开场怎么引导**：
- ✅ **合格**：它应该先问你问题（如"CP① 要先选号，你知道现有号有哪些吗？"），而不是直接告诉你做什么、怎么做。
- ✅ **更好**：它可能先抛器层快检（"halt.c 是源码还是构建产物？"），确认你器层立住了再进 CP①。
- ❌ **不合格**：它直接给方案（"第一步改 sysnum.h 填 27，第二步改 usys.pl..."）——这是代笔不是教学。

## 测试四：画像是否生成（测机制C）

**目的**：验证 AI 是否动态维护 profile.md。

**做完前面几个测试后，退出 claude，看文件**：
```bash
exit  # 退出 claude
ls -la profile.md 2>/dev/null && echo "✅ AI 生成了 profile.md" || echo "❌ 没生成"
cat profile.md  # 看它写了什么
```

**观察重点**：
- ✅ **合格**：profile.md 存在，且里面有五维达成度评估、卡点记录。
- ⚠️ **半合格**：生成了但内容空泛（全是模板没填）。
- ❌ **不合格**：根本没生成——说明 AI 没遵守机制C 规则。

## 测试五：跨 lab 画像传递（测机制C 进阶，可选）

**目的**：验证 lab2 的 AI 是否读 lab1 的画像。

```bash
# 先确保 lab1 有 profile.md（测试四生成后）
# 进 lab2 启动 claude
cd /home/hejunlin/xv6-ai-labs-km/lab2
claude
```
**说**：
```
我要做 lab2，先了解一下我现在该从哪开始。
```

**观察**：
- ✅ 合格：它去读了 `../lab1/profile.md`（你能看到它跑 cat 命令），然后基于你的 lab1 表现给建议。
- ❌ 不合格：它完全不知道你 lab1 的表现，当成新学生。
- ⚠️ 注意：lab2 的 CLAUDE.md 现在还没改（只有 lab1 改了），所以这个测试可能失败——这正常，说明 lab2 还没回灌机制C。这个测试等 lab2 做完再正式跑。

## 如果发现问题怎么处理

- **AI 不读参考就答**：说明 CLAUDE.md 机制A 的规则没硬到让它必须读。回来告诉我，我加强措辞（如改成"回答任何 CP 问题前必须先执行 base64 -d"）。
- **AI 提示太明显（L5）**：说明分寸规则没吃透。把它的原话发我，我针对性加反例。
- **AI 不生成画像**：说明机制C 没触发。可能是规则写得太靠后没读到。
- **AI 表现很好**：那 lab1 样板就验证有效，可以放心复制到 lab2~8。

> 关键：**把 AI 的原话尽量原样记下来**（截图或复制），尤其是它"做错"的地方。我看到原话才能精准改规则。
